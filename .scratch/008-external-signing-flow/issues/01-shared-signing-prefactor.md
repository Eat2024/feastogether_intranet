# 01: 共用簽署元件與副本讀取的前置重構

**What to build:** 讓外部簽署流程可以直接重用既有的簽署元件與個人副本讀取，但不改變任何現有行為。內部簽署人在「我的電子簽」看到的畫面、建立人與內部簽署人的副本下載，都和重構前完全相同。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 內部簽署畫面的簽名進度面板（簽名進度、「我已閱讀並同意上述文件內容」、確認簽署、拒絕簽署）抽成共用元件；可由參數決定是否顯示拒絕簽署、手機寬度是否固定在畫面底部。內部畫面改用它後外觀與操作不變。
- [ ] 同意條款步驟可由呼叫端傳入聲明內容與版本，並可隱藏「不同意，返回」；內部流程仍顯示原本的條款與按鈕。
- [ ] 文件檢視元件可由呼叫端指定 PDF 來源；未指定時沿用原本的來源。
- [ ] 後端讀取並驗證個人副本的邏輯改為可共用（呼叫端負責授權），建立人與內部簽署人的下載結果不變。
- [ ] 後端外部存取中重複的「以邀請憑證查詢簽署人與文件」抽成單一方法，外部 API 的行為與錯誤不變。
- [ ] 既有 server 單元、e2e 與 security 測試全數通過；client lint、build 通過；內部簽署頁人工比對無差異。

## 交付界線

只做重構，不新增端點、畫面或授權規則。
