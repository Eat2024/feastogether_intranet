# 05: 簽完立即下載本人副本

**What to build:** 外部簽署人送出簽名後留在完成頁，畫面先顯示副本產生中，產生完成後自動轉為「下載已簽署文件」，下載的 PDF 只有本人簽名與日期、附簽章驗證 QR Code，與建立人取得的該人副本相同。網路中斷後重送同一次簽名，會拿回既有結果而不是錯誤。

**Blocked by:** 01: 共用簽署元件與副本讀取的前置重構；02: 外部簽署人可從邀請信完成簽署

**Status:** ready-for-agent

- [ ] 外部存取區分「存取」與「簽署」：已簽者可讀取本人任務與下載本人副本，不比對期限、文件狀態與簽署期間；送出新簽名仍只限待簽者且在簽署期間內。
- [ ] 簽署成功不再清除外部存取，改設為瀏覽器關閉即失效的 session cookie，避免完成頁輪詢時因原簽署期限截止而中斷。
- [ ] 重送同一次已被接受的簽名，回傳既有結果；已簽者以新的請求再次簽署會被拒絕。
- [ ] 新增唯讀的外部任務查詢，供完成頁輪詢副本狀態，不寫入任何資料或稽核；開啟任務仍記錄開啟。
- [ ] 新增本人副本下載：副本已產生時回傳 PDF 附件（不快取、禁止 MIME 推測），沿用建立人下載的完整性檢查；尚未產生回「個人副本尚未產生」。
- [ ] 完成頁依設計稿呈現三種狀態：產生中（按鈕停用轉圈）、可下載、產製失敗（說明並請向文件發起人索取），並提示之後可隨時再次開啟邀請信中的連結下載；副本產生中或處理中時每 3 秒自動更新，可下載或失敗即停止。
- [ ] 外部 API 型別、請求與查詢沿用前端既有的 API 呼叫層架構；下載以一般連結直接下載附件。
- [ ] Spec 003（US3 驗收 6、FR-016、FR-026、外部邀請契約）與 Spec 004 中「外部簽完邀請失效」的記載加上「由 Spec 008 取代」註記，保留原文；後端 API 說明同步更新。
- [ ] 單元測試涵蓋存取判斷、重送與簽署寫入不變；e2e 驗證 session cookie、唯讀查詢不增加稽核、副本產生前回 409、產生後 200 且與建立人下載內容相同、重送 200；改寫既有「簽署後重送與開啟任務皆 401」的斷言，API 清單登錄新端點；security 驗證新端點錯誤不回顯 cookie。
- [ ] client lint、build 通過；實際簽署後在完成頁看到狀態由產生中轉為可下載並成功下載。
