# 09: 送出簽名綁定簽署人

**What to build:** 外部簽署人送出簽名時，系統確認送出的頁面確實屬於目前存取所對應的簽署人。同一個瀏覽器先後開啟同一份文件兩位簽署人的邀請、cookie 被後者覆蓋時，從前一個分頁送出的簽名會被拒絕，並提示重新開啟邀請信中的連結，不會把簽名記到另一位簽署人身上。

**Blocked by:** 05: 簽完立即下載本人副本

**Status:** claimed

- [ ] 外部送出簽名必須帶上頁面所屬的簽署人識別；後端與存取憑證對應的簽署人比對，不符時回 409「此頁面的簽署對象已變更，請重新開啟邀請信中的連結」，不建立簽署、不改變任何簽署人狀態。
- [ ] 內部簽署端點不受影響。
- [ ] 外部簽署頁送出時自動帶上頁面路由中的簽署人識別；收到不符錯誤時顯示該訊息，不顯示員工登入相關提示。
- [ ] 合法送出（含網路重試重送同一請求）照常成功。
- [ ] e2e 重現「同一文件兩位外部簽署人、cookie 被覆蓋」情境：舊分頁送出被拒、兩位簽署人都維持未簽；另驗證缺少或格式錯誤的簽署人識別回 400。
- [ ] API 契約與後端 API 說明同步更新；server lint、test、build、e2e 與 client lint、build 通過。
