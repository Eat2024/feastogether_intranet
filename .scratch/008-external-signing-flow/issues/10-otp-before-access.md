# 10: 外部簽署人通過驗證碼才能開啟文件

**What to build:** 外部簽署人在邀請確認頁按下「開啟電子簽署文件」後，系統寄一封含 6 位數驗證碼的信到同一個邀請信箱，畫面顯示驗證碼輸入頁（遮罩後的信箱、10 分鐘有效）。輸入正確驗證碼後才建立存取並進入外部簽署頁（待簽者）或完成頁（已簽者）；只持有邀請連結、收不到該信箱信件的人無法開啟文件或下載副本。

**Blocked by:** 06: 已簽者日後重新開啟連結下載

**Status:** claimed

- [ ] 按下開啟時先判斷邀請：失效顯示失效頁、尚未開始顯示尚未開始頁，兩者都不寄驗證碼；有效邀請（待簽者在簽署期間，或已簽者）才寄出驗證碼並顯示輸入頁（設計稿 ① 輸入驗證碼）。
- [ ] 驗證碼為 6 位數字、10 分鐘有效、只能使用一次；系統只保存雜湊，不保存明碼；新寄出的驗證碼使舊的立即失效。
- [ ] 輸入錯誤時顯示錯誤與剩餘次數（設計稿 ① 驗證碼錯誤）；同一驗證碼錯滿 5 次即失效；過期、已使用或已失效時提示重新開啟或重新寄送。
- [ ] 驗證成功才建立瀏覽器階段存取（關閉瀏覽器即失效，待簽者與已簽者相同）並導向外部簽署頁；驗證成功前不設 cookie、不顯示文件內容。關閉瀏覽器後重新開啟邀請連結需再次驗證。
- [ ] 驗證碼信只含驗證碼、10 分鐘有效、文件名稱與「若非本人操作請忽略」，不含任何連結；寄送失敗顯示可重試的說明頁，不建立存取、不保留驗證碼。
- [ ] 記錄驗證碼寄出、驗證成功、驗證失敗與錯滿失效的稽核事件，皆不含驗證碼；原有「邀請已開啟」稽核改在驗證成功時記錄。
- [ ] 驗證碼與 token 不進入 URL、log、錯誤訊息或稽核內容；新端點的 request body 不寫入 access log；兩個端點套用既有的依 IP 限流。
- [ ] 單元測試涵蓋驗證碼產生、雜湊比對、錯誤次數、過期與單次使用；e2e 以 fake 寄信攔截驗證碼，驗證完整流程、驗證前無 cookie、錯滿 5 次失效、10 分鐘過期、失效與尚未開始不寄信、稽核事件；既有 e2e 中建立外部存取的流程改為經過驗證碼。
- [ ] API 契約、Spec 003（FR-015）取代註記與後端 API 說明同步；server lint、test、build、e2e、security e2e 通過。

## 交付界線

「重新寄送」按鈕、60 秒冷卻與每小時 5 封上限屬 11；本票的輸入頁可先不提供重新寄送（驗證碼失效時回到邀請信重新開啟即可）。
