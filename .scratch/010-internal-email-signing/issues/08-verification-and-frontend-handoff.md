# 08: 整體驗收與前端串接交接

**What to build:** 將已整合的內部與混合簽署流程完成跨功能驗收，提供前端 agent 可依循且與實作一致的契約，清楚區分後端完成與尚未實作的畫面。

**Blocked by:** 05 簽署後透過 OTP 取得個人副本；06 內外部簽署人混合催簽；07 重新開放簽署並寄送新邀請。

**Status:** ready-for-agent

**Spec:** 010 — SC-001～008、全部 FR 的交付核對，尤其 FR-015～018。對應 T018 的容量驗證、T039～T044，並完成 T034 延後至真實副本流程的回歸。T001～T017、T019～T038 已分配至 01～07；T004、T009、T018、T034 的分工依各票註記，未完成完整任務前不可將原 tasks 整項勾選。

**執行約定:** 所有前置 resolved 後才整體驗收；本票不是將前票必要測試延到最後的理由。僅後端必要修正與交接文件，不實作 client、不新增遠端 issues／PR、不部署；驗收且整合後才 resolved，追加命令、結果及既有 commit 紀錄，不將建立票單視為提交或發布授權。

- [ ] 以合成內部及混合名單完整驗證選人→信箱檢查→發起→邀請→OTP→簽署／拒簽→副本下載，及催簽、補簽後的新舊授權，外部流程回歸通過。
- [ ] 驗證補簽只更新待簽者，已簽者原邀請重新 OTP 後仍下載相同副本，證據 hash 不變；SMTP 失敗不回退已發起／補簽狀態，重送不重複建立批次。
- [ ] 以 1、100、101、6,000 人量測員工解析與信箱核對，6,000 人信箱為 60 批、每批最多 100、併發不超過 4，無誤配、缺漏被忽略或部分發起；記錄耗時、記憶體與請求／代理期限風險，不擅自增加背景發起。
- [ ] 再驗組織樹 Redis 7,200 秒快取命中不續期、過期按需更新；信箱查詢不套用該快取，不新增排程、fallback、環境變數、依賴或資料表。
- [ ] access／application log 與 audit metadata 不洩漏員編清單、Email、OTP、token、cookie 或簽名；發現缺口只作本需求必要修正。
- [ ] 更新受影響的舊免 OTP 成功假設，保留拒絕驗證及 Email 成功流程；確認新測試實際收錄，不刪除／跳過安全測試，不回填、刪除或改寫歷史證據。
- [ ] 在隔離 MySQL／Redis 執行 server lint:check、unit、build、schema、e2e、security 及容量驗證；記錄實際命令與結果。無法執行的項目保持未完成並列風險，不以 mock 通過替代真實資料庫驗收。
- [ ] 核對 Swagger 與三份既有串接契約，涵蓋實際方法／路徑、request／response、錯誤 details、兩種認證、cookie／表單、GET 唯讀、舊個人入口 403、補簽自動寄信及空清單語意；只將已驗證 API 標為交付。
- [ ] 前端交接明列選人解析、草稿／信箱狀態、發起錯誤、邀請／OTP、簽署／拒簽、產製輪詢與下載、催簽／補簽的串接順序；前端不直連 fgapi、不用登入略過 OTP、不依 Email 合併人員。
- [ ] 完成 FR／SC 對照及原 spec、tasks、checklist、quickstart 的真實狀態更新，交付摘要分列後端、migration、config 無新增、前端未實作及未驗證限制；桌面／手機畫面、完整登出既有限制及 UAT／PRD 部署不宣稱完成。
