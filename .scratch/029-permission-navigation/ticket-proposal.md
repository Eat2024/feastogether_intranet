# 029 Tickets 拆分提案

本文件是 to-tickets Step 4 的待確認提案，未發布正式 tickets、未設定 ready-for-agent。使用者確認粒度與依賴後，才依本機 tracker 規範建立每張獨立文件。規格仍以 [029 spec](../../specs/029-permission-navigation/spec.md)、[tasks](../../specs/029-permission-navigation/tasks.md) 與 [plan](../../specs/029-permission-navigation/plan.md) 為準。

四張切片先把現有導覽設定集中，再交付能力導覽、身分切換隔離及撤權重驗。第一張是 skill 允許的必要小型前置重構，其他張都涵蓋可觀察行為與驗證，不按 types/API/UI 水平拆開。全部範圍沿現有前端，不新增後端或正式化原型。

## 1. 029-01：集中維護現有側邊選單

**Blocked by:** None (can start immediately)。閱讀027/028契約即可做現況盤點，不要求其實作完成。

**What it delivers:** 維護者只修改集中設定就能調整現有三個業務入口的名稱與順序；無效設定可定位且不顯示，現有固定側欄與嵌入行為保持。此票是導覽重構，不宣稱已有權限過濾。

**Acceptance criteria:**

- [ ] 現有電子簽列表、我的電子簽、歷史匯出文件維持路徑、順序及圖示，呈現元件不再重複硬編清單；不增加隱藏登入、管理頁或其他假入口。
- [ ] link 必有已知 route、module 與至少一個對應的已知能力；group 最多一層、無 href、子項只能為 link。空需求、跨 module、未知 route/permission、重複 key 或非法形狀均能定位且不默認放行。
- [ ] 設定改名/改順序可直接反映側欄，元件只取集中結果；群組 fixture 不成為正式業務選單。
- [ ] 子路徑選取正確，名稱相近但不同前綴的路徑不誤選；固定寬 permanent Drawer、MUI theme、鍵盤焦點、語意導覽及 iframe 隱藏保持，不新增收合模式。
- [ ] 已核對本人能力契約與既有登入成功/登出清理位置，記錄前置功能可用性但不保存個資或憑證；完成 client lint/build 與受控設定、嵌入回歸驗證。

**Task coverage:** T001、T002、T003、T004、T023、T024、T025。

## 2. 029-02：依本人有效能力呈現業務入口

**Blocked by:** 029-01、028-02（本人有效能力讀取，包含員工同仁基礎能力與 Super user 完整能力）。

**What it delivers:** 已登入同仁看到電子簽列表與我的電子簽，有匯出能力才看到歷史匯出入口；Super user 依真實能力自然看到三項。查詢未完成或失敗時沒有舊業務連結。

**Acceptance criteria:**

- [ ] 使用現有同源 API 層取得本人 actor/modules 快照，不解析角色名稱或 OAuth scope，不以 Super user 身分類型跳過設定驗證；沒有 cookie/token/入口或其他人資料進入 DTO 或 query key。
- [ ] 必要欄位、actor 類型、正整數員工識別及陣列字串形狀不合法、同 module 重複時整份回應視為讀取錯誤；合法未知能力忽略而不授權，不把錯誤回應解成全權限。
- [ ] 查詢使用目前路徑 key、零 stale/gc/retry、mount/focus 重驗及可取消請求；不改其他業務 query 預設，不持久化，不加全站權限 Provider。
- [ ] 同 module 精確能力採全部具備；獨立 link 與群組子項同樣受檢查、空群組隱藏，原設定與回應不被修改。
- [ ] 只有成功且 idle 的目前快照顯示連結；初始與重驗有載入提示、失敗可重試、無可用功能有明確訊息，fetching/paused/error 均不顯示舊連結。
- [ ] 真實同仁、文件建立者、管理員與 Super user 能力矩陣通過；隔離 fixture 驗證跨 module、多能力、空群組與獨立項，不把歷史匯出原型視為正式後端成果。client lint/build 通過。

**Task coverage:** T005、T006、T007、T008、T009、T010、T011、T012。

## 3. 029-03：切換身分後清除前任導覽與內部資料

**Blocked by:** 029-02、027-05（OAuth/WebView 單會話替換；其前置027-04已交付隱藏登入成功/登出與身分清理流程）。

**What it delivers:** 同瀏覽器從 Super user 切回員工後，前任全權限選單及內部資料不殘留；晚到的舊請求也無法覆蓋新身分。

**Acceptance criteria:**

- [ ] 成功登入/登出接入027既有清理流程，先取消再移除能力與內部身分相關 query，然後重新取得/導航；失敗保留原身分，不建立另一份登入或 session Provider。
- [ ] 清理精確限制在內部 query 白名單，不清外部簽署憑證、不改公開流程，不讀 HttpOnly cookie 建 key。
- [ ] 跨分頁改變 session 後，於下一次 focus、路徑變更或 refresh 偵測 actor 改變，先清前任內部資料再採完整新快照，不混用新能力與舊 actor。
- [ ] 延遲舊能力請求後切換身分，舊回應不能重新填入目前可見結果；重驗完成前不顯示全權限項目。
- [ ] Super user 顯示全部三項，切回同仁立即以新結果只留兩項；登入資料錯誤仍沿027局部401行為，沒有員工過期對話框誤觸。
- [ ] 不新增輪詢、BroadcastChannel、持久 session fingerprint 或裝置 cookie；記錄實際切換、延遲競態及外部流程回歸證據，client lint/build 通過。

**Task coverage:** T013、T014、T015、T016、T017。

## 4. 029-04：撤權與故障時安全重驗導覽

**Blocked by:** 029-03、028-09（整合切換驗收，包含角色/指派撤權下一請求生效及全部真實業務 API 拒絕越權）。

**What it delivers:** 權限變更不用重新登入即可在重驗時反映；內部業務權限不足只提示並合併重驗一次，登入失效、能力故障及離線有明確處理，不循環重抓或重送寫入。

**Acceptance criteria:**

- [ ] 實際撤銷額外能力後 refresh、focus、內部路徑切換都取得最新結果並移除項目，等待期間不顯示舊 links；靜止分頁不承諾推播，但後端下一請求立即拒絕。
- [ ] 只有內部業務403且錯誤碼為 AUTHORIZATION_DENIED 觸發取消/失效/單次能力重驗；同時多個拒絕合併成同一 in-flight 重驗，完成後可處理下一輪。
- [ ] 能力查詢自身403、登入/外部/公開錯誤與 CSRF 403 不觸發此機制，不形成無限 refetch；不自動重送已被拒絕的業務 mutation。
- [ ] 401清能力並沿既有 session 過期流程；027錯密碼401仍局部處理；403不導登入。能力非401錯誤只呈現一次可理解訊息與人工重試，paused 顯示離線狀態，不用舊資料 fallback。
- [ ] 完成真實角色、競態、401/403、離線及 iframe 矩陣；手動輸入隱藏頁面或直接呼叫受保護 API 不能越權取得資料，越權成功數為0，保留遮蔽敏感值的證據。
- [ ] client lint/build 通過；沒有 client test script 就不宣稱自動前端測試，無後端時相關驗收保持未完成。
- [ ] 記錄028先可用的部署前置及029只回退呈現、不撤回後端授權的回退方式；沒有新增 DB/env/dependency、角色管理/OAuth前端或原型正式化。

**Task coverage:** T018、T019、T020、T021、T022、T026、T027、T028。
