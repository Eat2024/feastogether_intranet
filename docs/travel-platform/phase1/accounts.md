### 這個功能做什麼

- 旅遊平台的人員資料由 HR 系統同步（經 OAuth 中心）。全公司同仁都能登入投票、報名，不需要在這裡建帳號。
- 帳號管理只管「能進後台的人」：管理員替 HR 同步來的在職同仁指定一個角色（角色在角色管理建立），這位同仁就能依角色權限使用後台。
- 列表依角色分頁。已發佈的帳號不能刪除，只能停用；只有從未發佈的草稿可以刪除。同仁在 HR 被標記離職後，每日 05:00 同步時自動停用。
- PRD 寫的現行系統：旅遊平台目前的後台帳號由 IT 建置，使用人數待同仁關係部提供。

### 目標與成功指標

| 目標 | 怎麼驗證 |
|---|---|
| 把 IT 從年度維運中移除 | 同仁關係部要讓新承辦人進後台、或調整承辦人角色時，能在本功能自己完成，不需要工程師建帳號或改資料庫 |
| 離職人員不留後台權限 | HR 標記離職後，下一次同步（每日 05:00）帳號就變成停用，稽核紀錄的操作者為「系統同步」 |

專案共有三個目標，本功能對應「把 IT 從年度維運中移除」。另外兩個是「流量尖峰保持順暢」與「堵住卡位漏洞」，分別在「旅遊報名」與「報名行程與梯次管理」處理。

### 使用者

| 使用者 | 身分由什麼決定 | 帳號來源 | 主要行為 |
|---|---|---|---|
| 管理員（有本功能權限的人，例：系統管理員、同仁關係部承辦人） | 本功能指派的角色；一個帳號一個角色 | HR 系統同步（經 OAuth）；上線時的第一位系統管理員由 PG 建立 | 替在職同仁指派角色（新增帳號）；更換角色，修改 Email 與備註；停用、重新啟用帳號；批次停用 |
| 同仁（間接相關） | HR 同步的在職狀態；投票、報名的資格名單 | HR 系統同步 | 不操作本功能；沒有後台帳號或帳號被停用，都不影響投票與報名 |

### 選單位置與範圍

```
權限管理（後台選單）
    ├─ 角色管理      另見《旅遊平台重構_PRD_角色管理》
    ├─ 帳號管理      本功能；只做 PC 版，不做手機版
    │    ├─ 列表頁（依角色分頁）
    │    └─ 編輯頁（標題「帳號設定」；新增與編輯共用同一頁）
    └─ 操作紀錄      畫面不用出，可最後開發
```

編輯頁只有一個區塊，沒有分頁標籤。

**本次範圍**：列表依角色分頁並顯示人數；搜尋姓名、工號、事業部；工號排序；勾選後批次停用；指派角色；刪除草稿帳號；編輯頁（角色、Email、備註、啟用開關，員工編號、姓名、事業部唯讀）；儲存草稿（只用於新增）、儲存並發佈、取消；停用與重新啟用；HR 同步（更新姓名、事業部、Email，離職自動停用，失敗時自動重試、寄告警信與恢復通知信）。

**不做的項目**：

| 不做 | 原因 |
|---|---|
| 刪除帳號 | 已發佈的帳號只能停用，保留稽核軌跡；草稿可以刪除 |
| 批次啟用 | 只做批次停用 |
| 密碼設定、恢復預設密碼 | 登入走 OAuth，密碼不在本系統；忘記密碼走登入頁的「忘記密碼」 |
| 建立 HR 沒有的人員（外部人員、旅行社） | 帳號只來自 HR 同步；旅行社不是系統使用者 |
| 批次新增帳號、匯入帳號 | 後台人數少，逐筆新增就好 |
| 一個帳號多個角色 | 一個帳號一個角色，換角色就是覆蓋 |
| 列出沒有後台角色的一般同仁 | 列表只列有後台角色的帳號 |
| 已發佈帳號的草稿版本 | 已發佈的帳號不能存草稿 |
| 角色的新增、編輯、刪除與權限勾選 | 屬於「角色管理」，另有 PRD |
| 操作紀錄查詢畫面 | 屬於「操作紀錄」，畫面不用出、可最後開發；本功能只負責寫入稽核紀錄 |
| 後台的「重新同步」按鈕 | HR 同步失敗時，由 IT 在旅遊平台的後端伺服器手動重跑 |
| 列表頁顯示最後同步時間 | 同步失敗改用告警信通知 IT 與系統管理員 |
| 匯入、匯出、下載 | 本功能沒有 |

樣式規則（全平台一致）：

- 使用 MUI Alert 實心樣式（`variant="filled"`）。錯誤為紅色 #D32F2F，成功為綠色 #2E7D32；文字與圖示白色 #FFFFFF。
- 圖示在左側：錯誤是圓圈驚嘆號，成功是圓圈打勾。圓角 4px。
- 文案放在 {Title}，需要補充時才放 {Description}；文字太長自動換行，不截斷。
- 位置：PC 與手機版都固定在畫面右上角、頁首下方，靠右對齊，頁面捲動時不移動。寬度：PC 依文字長度，最寬 600px；手機左右各留 16px。
- 5 秒後自動消失，沒有關閉按鈕。
- 畫面上同時只有一則：新的取代舊的，從新的出現時重新計算 5 秒。
- 不加遮罩、不鎖畫面。

不跳 toast 的情況：

- 已經有畫面回饋的成功操作：批次停用、停用、刪除草稿。
- 確認動作改用提醒視窗：取消、停用、批次停用、刪除草稿。
- 直接顯示在頁面上的訊息：欄位驗證錯誤（就地紅框）、「此角色尚未指派帳號」「查無符合的帳號」「查無符合的在職同仁」「已選取 N 筆」「HR 已標記離職」。
- 沒有權限時，選單直接不出現、按鈕直接不顯示。

### HR 同步通知信

| 信件 | 觸發 | 收件人 | 主旨 | 內容 |
|---|---|---|---|---|
| 同步失敗告警信 | 當天 05:00、05:30、06:00 三次同步都失敗；當天只寄 1 封 | IT 維運信箱（系統固定，資訊部提供，PG 寫在後端伺服器的設定檔，後台不顯示、不能改）；所有角色為系統管理員且狀態為啟用的帳號的 ⑳ Email，Email 空白的略過 | 【旅遊平台】HR 資料同步失敗 {yyyy/mm/dd} | 三次同步的時間、失敗原因與錯誤代碼；最後一次同步成功的時間；影響說明（恢復前帳號維持最後一次成功的資料，HR 已標記離職的同仁仍為啟用、仍能進後台）；處理方式（IT 在後端伺服器手動重跑；系統管理員可先在編輯頁 ⑱ 手動停用） |
| 同步恢復通知信 | 寄出告警信後，第一次同步成功（IT 手動重跑或隔天 05:00） | 同上 | 【旅遊平台】HR 資料同步已恢復 {yyyy/mm/dd} | 恢復的時間；這次更新筆數（資料更新 N 筆、離職停用 N 筆）；上次成功後共失敗幾次 |

兩封信都沒有附件。寄信失敗時記在同步執行紀錄（含錯誤代碼），不重寄。

## 功能需求

### 列表查詢與顯示

- **ACCT-01** 角色有帳號管理「查看」權限時，後台選單才出現帳號管理；沒有查看權限時，選單不出現本功能。
- **ACCT-02** 角色分頁依角色管理的順序排列，系統管理員固定第一，0 人的角色也顯示；進入列表時預設停在系統管理員分頁。
- **ACCT-03** 分頁人數＝指派到該角色的帳號數，含啟用、停用、草稿，與角色管理的人數相同；搜尋時人數不變。
- **ACCT-04** 列表只列有後台角色的帳號，不列一般同仁。預設依工號遞增排序，可切換遞減；其他欄位不能排序。
- **ACCT-05** 事業部、上次登入沒有值時顯示「－」，不顯示空白或 null。
- **ACCT-06** 上次登入顯示最後一次成功登入旅遊平台的時間（前台、後台都算），格式 YYYY/MM/DD HH:mm，台灣時間。
- **ACCT-07** 狀態欄依帳號狀態顯示啟用、停用、草稿三種樣式。
- **ACCT-08** 搜尋框預設收合。點 ④ 展開，空白時再點 ④ 收合；有輸入時按 Enter 或 ④ 執行搜尋。
- **ACCT-09** 搜尋比對姓名、工號、事業部，部分符合即列出；英文不分大小寫，關鍵字前後的空白自動忽略。
- **ACCT-10** 只搜尋目前分頁。切換分頁時保留關鍵字，並套用到新分頁；搜尋結果維持原排序，回到第 1 頁；清空關鍵字後恢復全部帳號。
- **ACCT-11** 角色還沒有帳號時，顯示「此角色尚未指派帳號」；搜尋沒有結果時，顯示「查無符合的帳號」。
- **ACCT-12** 分頁器每頁 20 筆，每頁筆數可選。

### 批次停用

- **ACCT-13** ⑤ 全選會勾選或取消目前分頁、目前這一頁的全部可勾選列；切換分頁或換頁時清除勾選。勾選至少 1 筆時，顯示「已選取 N 筆」，③ 變成可按。
- **ACCT-14** 按 ③ 時，系統算出 {M}＝勾選的帳號中「狀態為啟用、且不是自己」的數量，並跳批次停用提醒（含 {N}、{M}）。草稿、已停用、自己的帳號不會被異動。
- **ACCT-15** 提醒按「是」：{M} 個帳號改成停用，效果同單筆停用；列表狀態即時更新，清除勾選，⑯ 消失，不跳成功 toast；每個被異動的帳號各留一筆稽核紀錄。按「否」：關閉提醒，不異動，保留勾選。
- **ACCT-16** {M}＝0 時不跳提醒，改跳紅色 toast「勾選的帳號沒有可停用的項目_{錯誤代碼}」，不異動也不留紀錄。
- **ACCT-17** 整批一次寫入，不會只停用一半；連按「是」只執行一次。逾時或網路中斷時，整批不寫入，跳「網路連線異常」toast，保留勾選，可重試；重試時已經停用的帳號不再異動，也不重複留紀錄。

### 指派角色、編輯與儲存

- **ACCT-18** 按 ⑮ 指派角色，開啟編輯頁並先選 ⑰ 員工編號。選單只列 HR 同步為在職的同仁；已有帳號的同仁標「已有帳號（{角色名稱}）」；查無結果時顯示「查無符合的在職同仁」。
- **ACCT-19** 新增時選好員工後，自動帶入姓名、Email、事業部。
- **ACCT-20** 選到已有帳號（含草稿、停用）的同仁時，不另建帳號，直接切換為該帳號的編輯頁（同按 ⑫），帶出目前的角色、Email、狀態、備註。
- **ACCT-21** 已發佈的帳號：員工編號、姓名、事業部唯讀；啟用、Email、角色、備註可修改。
- **ACCT-22** 角色選單的選項與順序同角色管理；只有系統管理員看得到「系統管理員」選項。
- **ACCT-23** Email 選填；有填時必須符合格式，否則顯示「請輸入正確的 Email」並擋住發佈。備註超過 200 字無法輸入。
- **ACCT-24** 儲存草稿：只有新增中或仍是草稿的帳號可按，只檢查員工編號與角色。成功後狀態為「草稿」，跳綠色 toast「草稿已儲存」，留在編輯頁；草稿帳號不能使用後台，前台照常。
- **ACCT-25** 已發佈（啟用或停用）的帳號，儲存草稿反灰；即使有修改內容也一樣，只能按儲存並發佈或取消。
- **ACCT-26** 儲存並發佈：⑱ 開就存成「啟用」，關就存成「停用」。成功後跳綠色 toast「帳號已更新」，回到列表頁並停在該帳號（新）角色的分頁。啟用時，該同仁下一次操作就依角色取得後台權限。
- **ACCT-27** 更換已發佈帳號的角色：覆蓋原角色，不累加。該同仁不必重新登入，下一次操作就依新角色判斷，舊角色的功能立即不能用。原分頁人數 -1、新分頁 +1，角色管理的人數同步更新。
- **ACCT-28** 欄位驗證失敗：不存檔，留在編輯頁；錯誤欄位就地紅框，必填未填顯示「此欄位為必填」，其他顯示該欄位的專屬訊息；畫面捲到最上方的錯誤欄位；不用 toast。
- **ACCT-29** 新增時，員工已被其他管理員建立帳號：不存檔，⑰ 紅框顯示「該員工已有帳號」（兩人同時新增同一員工時，先儲存的成立）。員工已被 HR 標記離職：不存檔，⑰ 紅框顯示「該員工已離職，無法建立帳號」。
- **ACCT-30** 按 ㉖ 取消一律先跳取消提醒。按「是」：不存檔，回到列表頁，並留一筆稽核紀錄；按「否」：維持原頁面，已填內容保留。
- **ACCT-31** 存檔失敗、逾時或網路中斷：不存檔，跳紅色 toast「儲存失敗，請稍後再試_{錯誤代碼}」，已填內容保留，可重試。連按儲存只存一次，也只留一筆紀錄。兩位管理員同時編輯同一帳號時，以後儲存的為準，兩筆稽核紀錄都保留。

### 停用與重新啟用

- **ACCT-32** 已發佈的帳號把 ⑱ 切到關閉，立即跳停用提醒。按「是」：立即停用，不必再按儲存並發佈；角色保留，帳號仍在原角色分頁；同頁其他未儲存的修改不存檔；留稽核紀錄，回到列表頁。按「否」：不停用，開關回到開啟，維持原畫面。
- **ACCT-33** 停用後，該同仁下一次操作起就不能使用後台（後台選單消失，後台功能顯示無權限）；前台照常，仍可登入、投票、報名。
- **ACCT-34** 重新啟用：把停用帳號的 ⑱ 切到開啟，按儲存並發佈。狀態變為「啟用」，依原角色恢復後台權限；同頁其他修改一起存檔，跳「帳號已更新」，留稽核紀錄。前提是該同仁在 HR 仍為在職。
- **ACCT-35** 編輯自己的帳號時，⑱ 與 ㉒ 唯讀，⑳ Email、㉔ 備註可以修改並儲存。
- **ACCT-36** HR 已標記離職的帳號，⑱ 唯讀，旁邊顯示「HR 已標記離職」。
- **ACCT-37** 停用時逾時或網路中斷：不寫入，跳「網路連線異常」toast，開關回到開啟，可重試。

### 刪除草稿帳號

- **ACCT-38** ㉙ 刪除只在草稿帳號的編輯頁顯示（頁尾左側）；新增中、已發佈的帳號都不顯示。按下後先跳刪除草稿提醒。
- **ACCT-39** 提醒按「是」：刪除這筆帳號（角色指派），帳號從列表消失，原分頁與角色管理的人數 -1；該同仁的 HR 資料與前台使用不受影響，之後可再用 ⑮ 重新指派；留一筆稽核紀錄，行為記「刪除草稿」，並記錄刪除前的角色、Email、備註；回到列表頁並停在原分頁，不跳 toast。角色若因此變成 0 人，就能在角色管理刪除。按「否」：關閉提醒，留在編輯頁，不留紀錄。
- **ACCT-40** 已發佈的帳號不能刪除：畫面沒有入口，直接呼叫刪除也會被拒絕，帳號不變。
- **ACCT-41** 按「是」的當下，若這筆草稿已被其他管理員發佈：不刪除，畫面重新載入為已發佈帳號的編輯頁，不再顯示 ㉙。連按「是」只刪一次；重試時若第 1 次其實已經刪掉，不報錯，直接回到列表頁。網路中斷時不刪除，跳「網路連線異常」toast。
- **ACCT-42** 刪除草稿需要帳號管理的「新增」權限，因為角色管理沒有帳號管理的「刪除」勾選框。

### HR 同步

- **ACCT-43** 每日 05:00 執行 HR 同步，以員工編號比對本系統所有帳號（任何狀態）：姓名、事業部以 HR 為準更新；Email 在 HR 有信箱時以 HR 為準覆蓋（包含管理員改過的值），HR 沒有信箱時保留原本的值。
- **ACCT-44** HR 標記離職，或 HR 查無該員工編號時，啟用、草稿的帳號改成「停用」，角色保留不清空，稽核紀錄的操作者記「系統同步」。同步重跑時，已停用的帳號不再異動，也不重複留紀錄。
- **ACCT-45** 離職後 HR 又改回在職（回任）：帳號維持停用，⑱ 恢復可操作，由管理員決定要不要重新啟用。回任這次同步不改狀態，也不留帳號稽核紀錄。
- **ACCT-46** 同步失敗（HR 系統連不上、逾時、回傳資料有誤或寫入失敗）時，整批不寫入，帳號維持前一次成功的資料。05:30、06:00 各自動重試 1 次，任一次成功就不再重試；三次都失敗才寄告警信（當天只寄 1 封）；寄出告警信後第一次成功時寄恢復通知信；隔天 05:00 照常執行，重新計算三次。
- **ACCT-47** 每次同步執行（含自動重試、IT 手動重跑）各留一筆同步執行紀錄，內容包含：開始與結束時間、成功或失敗、當天第幾次（手動另外註明）、失敗原因與錯誤代碼、資料更新與離職停用筆數、告警信與恢復信是否寄出。這份紀錄存在後端伺服器供 IT 查詢，後台畫面不顯示。
- **ACCT-48** 同步與管理員同時異動同一帳號時，離職停用優先；管理員的儲存若會把離職帳號改回啟用，就不寫入。
- **ACCT-49** 後台沒有「重新同步」按鈕，列表頁也不顯示最後同步時間；同步失敗時，由 IT 在後端伺服器手動重跑。

### 權限與系統管理員保護

- **ACCT-50** 依權限矩陣顯示按鈕，沒有權限的按鈕不顯示（見〈業務規則與驗證〉）。
- **ACCT-51** 系統至少保留一個啟用中的系統管理員帳號：會讓啟用中的系統管理員變成 0 個的停用或換角色，一律不寫入。系統在儲存時檢查，防止直接呼叫或併發造成。HR 同步的自動停用不受這條限制；若因此沒有啟用中的系統管理員，由 PG 依上線程序補建。
- **ACCT-52** 只有角色為系統管理員的帳號，才能把系統管理員指派給別人，或把別人的系統管理員換成其他角色。其他角色看不到系統管理員選項，也看不到系統管理員帳號列的 ⑫ 編輯與 ⑬ 勾選；直接呼叫儲存也不寫入。
- **ACCT-53** 權限即時生效：停用或換角色後，該同仁不必登出；後端每一次後台請求，都依「目前」的角色與狀態判斷，不能只看登入當下的權限。
- **ACCT-54** 上線時第一位系統管理員由 PG 建立，之後由系統管理員在本功能指派。

### 稽核紀錄

- **ACCT-55** 以下操作各留一筆稽核紀錄，不覆蓋（批次停用時每個帳號各一筆）：儲存草稿、儲存並發佈、停用、重新啟用、批次停用、HR 同步停用、刪除草稿、取消。
- **ACCT-56** 每筆紀錄包含：操作者（員工編號與姓名，或「系統同步」）、行為、時間（台灣時間，精確到秒）、被異動帳號的員工編號與姓名，以及異動前後的角色、Email、狀態、備註。紀錄在「操作紀錄」查詢，唯讀、不能刪除。

### 通知

- **ACCT-57** 本功能只寄 HR 同步的兩種信（告警信、恢復通知信）；帳號新增、停用都不通知該同仁，也不發 MOT 通知。

### 非功能

- **ACCT-58** 壓測兩種情境都要通過：一是同一時間湧入 3,000 人，二是陸續登入到 3,000 人、期間沒人登出，兩者都持續操作 30 分鐘以上。通過標準：
  - 儲存草稿、儲存並發佈、批次停用、停用要在 1 秒內完成，狀態欄與分頁人數同步更新（時間是專案管理部的建議，待資訊部確認）。
  - 成功率 99.5% 以上。
  - 壓測結束後，角色、狀態與稽核紀錄筆數和實際操作一致，沒有重複寫入或漏記。
- **ACCT-59** 所有 API 呼叫都要設 timeout。PG 要設計錯誤代碼表（code 與對應的 msg）；HR 同步的錯誤代碼要能區分失敗原因（HR 系統連不上、逾時、回傳格式錯誤、寫入資料庫失敗、寄信失敗）。
- **ACCT-60** 個資：列表與編輯頁只顯示員工編號、姓名、事業部、Email，不顯示身分證字號與生日；本系統不儲存密碼。
- **ACCT-61** 只做 PC 版，不做 RWD；要支援 14 吋、22 吋、27 吋螢幕。
- **ACCT-62** 專案開發規則：匯出文字檔前要先處理字串裡的特殊控制字元（本功能沒有匯出）；要留意 SQL Injection 與跳脫字元風險；OWASP Top 10 漏洞必須修復。

## 業務規則與驗證

### 帳號狀態

```
1 草稿 ──→ 2 啟用 ⇄ 3 停用
   │                  ↑
   └──────────────────┘
```

| 狀態 | 怎麼進入這個狀態 | 該同仁的後台 | 該同仁的前台 | 系統動作 |
|---|---|---|---|---|
| 草稿 | 新增時按「儲存草稿」 | 不能使用 | 照常（依 HR 在職狀態與資格名單） | 存檔；計入分頁人數 |
| 啟用 | 按「儲存並發佈」且 ⑱ 開；或停用的帳號重新啟用 | 依角色權限 | 照常 | 存檔；下一次操作就生效 |
| 停用 | 已發佈帳號關閉 ⑱ 並按「是」；批次停用；發佈時 ⑱ 是關的；HR 同步標記離職 | 不能使用 | 照常；但 HR 離職的人無法登入（OAuth） | 角色保留；留稽核紀錄 |

- 已發佈（啟用或停用）的帳號不能回到草稿。
- 已發佈的帳號不能刪除；草稿可以刪除，刪除後帳號不留，只留稽核紀錄。
- 草稿、啟用的帳號遇到 HR 標記離職，同步時改為停用。

### 同仁在職狀態（來自 HR，不由本功能維護）

| 狀態 | 對本功能的影響 |
|---|---|
| 在職 | 出現在 ⑰ 員工編號選單；帳號可以重新啟用 |
| 離職 | 不出現在 ⑰ 選單；同步時帳號改為停用，⑱ 唯讀；無法登入旅遊平台 |

### 角色

- 系統管理員（Admin）是系統固定的角色，全部功能全開，名稱與權限不能修改，分頁固定第一。
- 其他角色在角色管理新增，名稱與數量不限（例：同仁關係部、部門主管、財務人員）。本功能只負責把角色指派給帳號。
- 角色沒有草稿狀態，存了就生效，立刻出現在 ㉒ 選單與 ① 分頁。角色還有帳號時不能刪除，所以帳號不會遇到「角色被刪掉」的情況。
- 一個帳號只能有一個角色。

### 權限矩陣

權限欄有五個動作：查看、新增、修改、刪除、匯出。每個動作在角色管理中分開勾選；系統管理員全開。

| 動作 | 控制的按鈕或畫面 |
|---|---|
| 查看 | 選單出現帳號管理、可進入列表頁；① 角色分頁、② 搜尋框、④ 搜尋、⑦ 工號排序、⑭ 分頁器 |
| 新增 | ⑮ 指派角色；編輯頁 ㉙ 刪除（草稿） |
| 修改 | ⑫ 編輯、⑤ 全選、⑬ 勾選、③ 批次停用；編輯頁 ⑱ 啟用、⑳ Email、㉒ 角色、㉔ 備註、㉗ 儲存草稿、㉘ 儲存並發佈；另受系統管理員保護規則限制 |
| 刪除 | 角色管理沒有帳號管理的「刪除」勾選框，刪除草稿改由「新增」權限控制 |
| 匯出 | 不適用，本功能沒有匯出 |

### 資料範圍與前台資格

後台權限與前台資格是兩套獨立的機制：

| 項目 | 由什麼決定 | 例子 |
|---|---|---|
| 資料範圍 | 不分部門：有查看權限的管理員看得到全部帳號 | 人力資源部的管理員有查看權限，就看得到各分頁的全部帳號，不會只看到人力資源部的人 |
| 能否登入旅遊平台 | HR 同步的在職狀態（在職才能以 OAuth 登入）；帳號管理的帳號與角色不影響能否登入 | 帳號被停用或根本沒有帳號的同仁，只要在職就能登入，只是看不到後台選單。有帳號、狀態為啟用且已指派角色的同仁，登入後看得到後台選單，能用哪些功能由角色權限決定 |
| 前台投票、報名資格 | 投票活動設定、報名活動設定匯入的資格名單（以員工編號比對）；帳號與角色不影響 | 不在某場投票資格名單上的人，即使是系統管理員也不能投；在名單上的人沒有後台帳號也照樣能投 |

### 併發與重送

- 兩位管理員同時編輯同一帳號，或同時切換啟用狀態時，以後儲存的為準，兩筆稽核紀錄都保留。
- 兩位管理員同時新增同一員工時，先儲存的成立，後儲存的顯示「該員工已有帳號」。
- 所有寫入操作重試時不能重複寫入：已停用的帳號不再停用一次，也不因為「已經是停用」而報錯；新增重試後只會有 1 個帳號；批次停用重試後，紀錄筆數不會加倍。
- HR 同步與管理員同時異動時，離職停用優先。

## 登入、員工資料來源與 OAuth

以下是本頁和登入方式、員工資料來源、OAuth 有關的 PRD 原文重點。這些點和公司的 OAuth server（feastogether_oauth）直接相關；跟它現況的比對放在〈待釐清問題〉。

- **登入方式是 OAuth**：PRD 引用《功能清單》Q-20「登入方式」，已於 2026-09-16 結案為 OAuth 登入。旅遊平台不設定密碼、不提供恢復預設密碼、不儲存密碼；忘記密碼走「登入頁的『忘記密碼』」。
- **能不能登入只看 HR 在職狀態**：「在職才能以 OAuth 登入」。帳號管理的帳號、角色、啟用狀態都不影響能否登入，只決定後台權限。
- **離職者的登入訊息**：UC-05-01 引用《功能清單》S0-01：已離職的人登入時統一顯示「無法登入，請洽人資」。
- **員工資料來源**：員工編號、姓名、在職狀態來自「HR 系統同步（經 OAuth 中心）」；事業部、信箱也來自 HR 同步。每日 05:00 同步，失敗時 05:30、06:00 重試。HR 不會建立本功能的帳號，帳號一律由管理員指派角色產生。
- **員工清單**：⑰ 員工編號下拉要列出全部在職同仁，並能用員工編號或姓名搜尋。
- **上次登入**：每次 OAuth 登入旅遊平台成功時記錄，前台、後台都算。
- **權限每次請求都重新判斷**：停用或換角色後，該同仁不必重新登入，下一次後台請求就依新權限判斷。停用不會讓同仁登出，前台照常可用。
- **第一位系統管理員**由 PG 在上線時建立。
- **Email**：預設帶入 HR 信箱，管理員可修改；HR 有信箱時，每日同步會覆蓋回 HR 的值。
