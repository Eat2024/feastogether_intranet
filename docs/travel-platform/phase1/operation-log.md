**優先度：最後有時間再做**（依頁面名稱）

## 概述

ClickUp 頁面本文只有三行開發提醒，沒有截圖、附件或欄位說明：

- 系統共用，拿程式 不出畫面，央廚系統延用
- **匯出文字檔前，請先處理好字串內的特殊控制字元**
- **留意SQL Injection、跳脫字元風險**

依第一行，操作紀錄沿用央廚驗收系統的程式，不另外出設計稿。

這一頁沒寫的內容，散見於同一份 PRD 的其他頁面與連結文件。以下各節照錄這些出處，並逐條標明來源：

- 《旅遊平台重構_PRD_帳號管理》v0.9：〈帳號管理〉頁連結的 Drive 檔案，見 [accounts.md](accounts.md)
- 《旅遊平台重構_PRD_角色管理》v0.7：同一個 zip 檔內
- ClickUp〈權限管理-角色管理 (央廚)〉（page id `2kzka7qd-9058`）的 Story 4

選單位置：後台選單「權限管理 > 操作紀錄」，與角色管理、帳號管理同層。兩份旅遊平台 PRD 的 Sitemap 寫法如下：

- 帳號管理 PRD：「畫面不用出，可最後開發」
- 角色管理 PRD：「畫面可最後開發，資料須優先同步紀錄」

## 畫面與欄位

PRD 沒有操作紀錄的畫面、欄位、篩選或排序規格。以下是其他功能 PRD 規定要寫入、並「於操作紀錄查詢」的紀錄內容。

### 帳號管理寫入的稽核紀錄（帳號管理 PRD 第 8、13 章）

| 項目 | 內容 |
|---|---|
| 寫入時機 | 儲存草稿、儲存並發佈、停用、重新啟用、批次停用、HR 同步停用、刪除草稿、取消；一次操作一筆，不覆蓋；批次停用時每個被異動的帳號各一筆 |
| 操作者 | 員工編號與姓名；HR 同步造成的停用記「系統同步」 |
| 行為 | 例：刪除草稿 |
| 時間 | 台灣時間，精確到秒 |
| 被異動的帳號 | 員工編號與姓名 |
| 異動內容 | 異動前後的角色、Email、狀態、備註 |

### 角色管理寫入的稽核紀錄（角色管理 PRD 第 8、13 章）

| 項目 | 內容 |
|---|---|
| 寫入時機 | 儲存、排序、改名、刪除、取消；一次操作一筆，不覆蓋 |
| 操作者 | 員工編號與姓名 |
| 行為 | — |
| 時間 | 台灣時間，精確到秒 |
| 異動內容 | 角色名稱，以及異動前後的權限差異 |

### 不在操作紀錄顯示的紀錄

HR 同步執行紀錄存在後端伺服器，供 IT 查詢，後台畫面不顯示（帳號管理 PRD 第 13 章）。這份紀錄包含：

- 開始與結束時間
- 成功或失敗
- 當天第幾次
- 失敗原因與錯誤代碼
- 更新筆數
- 告警信與恢復通知信是否寄出

### 央廚版的對應功能（〈權限管理-角色管理 (央廚)〉Story 4，供對照）

央廚驗收系統的「操作審計日誌」本期只做後端，沒有畫面。內容如下：

- 每筆日誌包含操作時間、操作人帳號、操作類型、角色名稱、變更前後的差異（JSON 格式）。
- 提供 API，可依時間範圍、操作類型篩選查詢。
- 提供 API，可匯出 CSV。
- 日誌保存期限待 PM 確認合規要求（建議最短 6 個月）。
- QA 以 Postman 或同等工具驗收，本期不需 UI 截圖。

## 功能需求

- **LOG-01** 後台選單「權限管理」下有「操作紀錄」，與角色管理、帳號管理同層（兩份旅遊平台 PRD 的 Sitemap）。
- **LOG-02** 角色的「查看」權限決定能否使用操作紀錄。在角色管理勾選權限時，操作紀錄只有「查看」與「匯出」兩個勾選框，沒有新增、修改、刪除（角色管理 PRD〈功能項目清單〉）。
- **LOG-03** 帳號管理、角色管理寫入的稽核紀錄，都在操作紀錄查詢（兩份 PRD 第 13 章）。
- **LOG-04** 稽核紀錄唯讀，不能刪除（兩份 PRD 第 13 章）。
- **LOG-05** 稽核紀錄的寫入不等操作紀錄畫面：畫面可以最後開發，但資料要先開始記錄（角色管理 PRD Sitemap「資料須優先同步紀錄」；帳號管理 PRD 非範圍「本功能只負責寫入稽核紀錄」）。
- **LOG-06** 匯出文字檔前，要先處理字串裡的特殊控制字元（本頁）。

## 業務規則與驗證

- 操作紀錄不另外出設計稿，沿用央廚系統的程式（本頁「拿程式 不出畫面，央廚系統延用」）。
- 要留意 SQL Injection 與跳脫字元風險（本頁）。旅遊平台 PRD 另有專案規則「OWASP Top 10 漏洞須修復」（帳號管理 PRD 開頭與〈帳號管理〉頁）。
- 稽核紀錄的時間一律用台灣時間，精確到秒；一次操作一筆，不覆蓋舊紀錄（兩份 PRD 第 13 章）。

## 待釐清問題

1. **畫面規格完全沒有**
   - 現況：本頁寫「不出畫面」，兩份 PRD 也只寫「可最後開發」。
   - 要問：要照搬央廚系統的哪個畫面？央廚的對應功能本期只有後端 API、沒有畫面（〈角色管理 (央廚)〉Story 4），那「拿程式」拿的是什麼？列表要有哪些欄位、篩選條件（時間範圍、操作類型、操作者、被異動對象？）、排序、分頁？
2. **匯出的格式與內容**
   - 現況：本頁要求「匯出文字檔前處理特殊控制字元」，角色管理 PRD 也給操作紀錄「匯出」權限；但旅遊平台 PRD 沒寫格式。央廚版是 API 匯出 CSV。
   - 要問：匯出的格式（CSV？）、欄位、範圍（依篩選結果？）、筆數上限是什麼？
3. **哪些功能要寫入操作紀錄**
   - 現況：目前只看到帳號管理、角色管理規定寫入。
   - 要問：投票活動設定、報名活動設定等其他後台功能的異動，也要進操作紀錄嗎？登入、登出、名單下載這類事件要不要記？
4. **兩個來源的欄位不一樣**
   - 現況：帳號管理記「異動前後的角色、Email、狀態、備註」，角色管理記「角色名稱與權限差異」；央廚版用 JSON 存變更前後的差異。
   - 要問：查詢畫面要怎麼呈現兩種結構不同的異動內容？
5. **保存期限**
   - 現況：帳號管理 PRD Q-12、角色管理 PRD Q-11、央廚版開放議題都寫「建議至少 6 個月，待法務確認」。
   - 要問：保存期限多久？到期後要刪除還是封存？
6. **「系統共用」的範圍**
   - 現況：本頁寫「系統共用，央廚系統延用」。
   - 要問：旅遊平台與央廚驗收系統的操作紀錄是共用同一份資料，還是各自獨立？
7. **與 HR 同步執行紀錄的界線**
   - 現況：帳號管理 PRD 說同步執行紀錄只存在後端伺服器、後台不顯示；但同步造成的帳號停用（操作者「系統同步」）會進稽核紀錄。
   - 要問：確認操作紀錄只顯示逐帳號的稽核紀錄，不顯示同步執行紀錄。
8. **「最後有時間再做」與第一期的關係**
   - 現況：頁面名稱表示優先度最低，但稽核紀錄要從第一期就開始寫入。
   - 要問：如果第一期沒做查詢畫面，稽核與合規需要查詢時，由誰、用什麼方式查？
