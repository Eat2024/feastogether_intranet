## 概述

- 這份是「庫存驗收系統」（央廚驗收系統）的角色管理 PRD，不是旅遊平台的需求。它和旅遊平台版的關係見〈與另一版本的差異〉。
- 目的：提供一個可擴充的角色與權限管理功能。系統管理員透過 UI 自行定義業務角色、設定功能權限、控管使用者能存取的功能，不需要寫程式。
- PRD 列出的核心價值：
  - 防止人員越權：以角色控管細部權限。
  - 支援業務擴充：可隨組織需求新增角色。
  - 簡化設定：管理員透過 UI 設定，不需寫程式。
  - 完整操作稽核：所有角色變更都留下紀錄，方便事後追查與合規。
- PRD 列出的上線目標：
  - 完成角色與權限管理系統。
  - 支援 100 人以上同時使用（壓測基準）。
  - 完整記錄新增、修改、刪除的操作日誌。
  - 支援匯出日誌：本期只提供後端 API，不做 UI。
- 使用者：系統管理員。
- 選單路徑：首頁 / 權限管理 / 角色管理。
- 帳號：帳號不可刪除。帳號來源是 OAuth，OAuth 再從 HR 同步。
- 角色與帳號（本期）：一個帳號只能綁一個角色。未來若要支援多角色，需另提需求。

## 功能需求

### 角色與管理員保護

- **ROLE-CK-01**：系統初始化時，自動建立「管理員」角色，擁有所有功能的全部權限；DB 中這個角色帶有「不可修改」flag。
- **ROLE-CK-02**：在「管理員」分頁，編輯、刪除、改名功能全部 disabled（UI）。
- **ROLE-CK-03**：後端拒絕修改或刪除管理員角色。直接用 API 修改或刪除時回傳 403。
- **ROLE-CK-04**：頁面頂端以分頁顯示每個角色。切到某個分頁時，唯讀顯示該角色的權限。

### 新增與編輯

- **ROLE-CK-05**：管理員可以按「新增」建立自訂角色，填寫角色名稱（必填）和描述（選填）。
- **ROLE-CK-06**：新增的角色預設所有權限都不勾。
- **ROLE-CK-07**：角色名稱在同一系統內不可重複。儲存時由後端驗證，重複時回傳並顯示明確的錯誤提示。
- **ROLE-CK-08**：管理員可以編輯自訂角色的名稱、描述和權限設定。按右上角「編輯」進入編輯模式，底部顯示「儲存」「取消」。
- **ROLE-CK-09**：按「取消」會回到編輯前的狀態，不保留這次的變更。

### 權限設定

- **ROLE-CK-10**：權限清單以功能模組分組，呈現為樹狀，可以展開或收合。
- **ROLE-CK-11**：每個功能項目都可以分別勾選檢視、新增／編輯、刪除、列印／匯出。
- **ROLE-CK-12**：勾選模組層「全選」時，該模組下所有功能的所有權限都會勾選；取消時全部取消。
- **ROLE-CK-13**：勾選「新增／編輯」或「刪除」時，同一列的「檢視」會自動勾選。
- **ROLE-CK-14**：按「儲存」後，新權限從下一個 API 請求開始生效，不需要重新登入。已登入的 session 會在下一個 API 請求時強制重新驗權。
- **ROLE-CK-15**：所有權限變更都由後端再驗證一次，前端勾選只影響畫面。

### 刪除

- **ROLE-CK-16**：刪除前，系統會檢查該角色綁定的帳號數：
  - 帳號數 ≥ 1 時阻止刪除，並提示「該角色目前有 N 個帳號，請先至帳號管理重新指派後再刪除」。
  - 後端 API 要回傳具體的帳號數量。
- **ROLE-CK-17**：確認刪除前會顯示二次確認 Dialog。帳號數為 0 時，刪除流程可以正常完成。

### 操作稽核（後端，本期無 UI）

- **ROLE-CK-18**：後端記錄所有角色的新增、修改、刪除操作：
  - 新增：記錄操作人、時間、角色名稱。
  - 權限修改：記錄修改前後的 diff。
- **ROLE-CK-19**：每筆日誌包含以下欄位：
  - 操作時間
  - 操作人帳號
  - 操作類型
  - 角色名稱
  - 變更前後的 diff（JSON 格式）
- **ROLE-CK-20**：提供日誌查詢 API，可依時間範圍和操作類型篩選。
- **ROLE-CK-21**：提供 API 把日誌匯出成 CSV。CSV 欄位包含時間、操作人、類型、角色、diff。

### 非功能需求

- **ROLE-CK-22**：效能
  - 頁面載入少於 2 秒，查詢回應少於 500ms。
  - 以 100 人同時使用壓測，P95 不超標。
- **ROLE-CK-23**：擴充性：支援 100 個以上的自訂角色、1000 個以上的權限節點，效能不下降，並以壓測報告佐證。
- **ROLE-CK-24**：資料備份：每日自動備份，可恢復 30 天內的資料。由 SA 提供備份策略文件。
- **ROLE-CK-25**：安全性：由 SA 提供 API 防護設計文件。

## 業務規則與驗證

| 規則 | 內容 |
| --- | --- |
| 管理員角色保護 | 「管理員」分頁的編輯、刪除、改名全部 disabled，後端也驗證。DB flag 標記為不可修改 |
| 角色名稱唯一 | 同一系統內不可重名，儲存時由後端驗證並回傳錯誤訊息 |
| 刪除前置檢查 | 綁定帳號數 ≥ 1 時禁止刪除，要先到帳號管理重新指派 |
| 最少一名管理員 | 系統至少要保留一個擁有管理員角色的啟用帳號。在帳號管理模組刪除或停用帳號時一併檢查 |
| 權限即時生效 | 儲存後，下一個請求立即套用新權限，不需登出 |
| 全選 | 勾選模組層「全選」時勾選該模組全部權限，取消時全部取消 |
| 權限相依 | 勾選「新增／編輯」或「刪除」時，「檢視」自動勾選 |
| 一帳號一角色 | 本期一個帳號只能綁一個角色 |
| 帳號不可刪除 | 帳號來源是 OAuth，OAuth 從 HR 同步 |
| 新角色預設 | 所有權限都不勾 |
| 日誌保存期限 | 待 PM 與法務確認合規要求（PRD 建議至少 6 個月） |

## 與另一版本的差異

另一版本指 ClickUp「角色管理」（page id `2kzka7qd-8338`），文件為 `roles.md`。

### 關係判斷

兩份不是同一功能的新舊版，也不是草稿和定稿，而是不同系統的角色管理：

- 本頁是「庫存驗收系統（央廚驗收系統）」已有的角色管理 PRD。
- 旅遊平台的角色管理會沿用央廚的程式，所以本頁被放在旅遊平台 PRD 底下當參考基礎。
- 旅遊平台實際要做的規格，以「角色管理」頁連結的《旅遊平台重構 角色管理 PRD v0.7》為準。

判斷依據：

1. 本頁寫「為庫存驗收系統提供……角色與權限管理平台」。Figma 檔名是「央廚驗收系統」。截圖左上角是「庫存驗收系統」，選單模組是央廚驗收、物料資訊，角色是央廚人員、採購人員、門市人員。這些都和旅遊業務無關。
2. 「角色管理」頁寫「系統共用，拿程式 不出畫面，央廚系統延用」。旅遊平台版 PRD 的〈來源追溯〉寫「央廚驗收系統的角色管理（拿程式延用）」。
3. 旅遊平台版 PRD v0.1 的變更紀錄寫「參照 ClickUp〈權限管理-角色管理 (copy)〉（央廚驗收系統角色管理 PRD）」。
   - 推論那一頁就是本頁，可能後來改名為「(央廚)」。
   - 依據：本頁建立於 2026-10-16，早於旅遊版 v0.1 的 2026-10-22，內容也吻合。
   - 頁名不同，這點列入待釐清。
4. 旅遊平台版的風險表列出「沿用央廚程式但規則不同」。附錄 A 也逐項把和「央廚版」不同的地方標成【差異】並記下決議，可見旅遊版是在央廚版之上修改的另一份規格。

## 待釐清問題

1. **本頁和旅遊版參照的「(copy)」頁是否為同一頁**
   - 現況：旅遊版 PRD v0.1 寫的是參照〈權限管理-角色管理 (copy)〉，但 ClickUp 上只有「權限管理-角色管理 (央廚)」。
   - 要問：兩者是否為同一頁？本頁目前是否就是央廚系統的現行規格？
2. **「描述」欄位要不要做**
   - 現況：Story 1、Story 3 寫角色有「描述（選填）」，但新增角色截圖只有「角色名稱」。
   - 要問：要不要做「描述」？如果要，它的長度和顯示位置是什麼？
3. **權限表文字和截圖不一致**
   - 現況：§3.2 文字表寫物料資訊 4 個功能項目和帳號管理都有「刪除」。但截圖中，「管理員」分頁（理論上全部權限）這幾列都沒有刪除勾，新增頁也沒有刪除勾選框。另外，PRD 也寫「帳號不可刪除」。
   - 要問：這些功能項目到底有沒有「刪除」動作？哪一份才是正確的？
4. **「刪除/清空」的「清空」是什麼意思**
   - 現況：列表截圖的欄名是「刪除/清空」，編輯截圖和文字都是「刪除」。
   - 要問：「清空」代表另一個動作嗎？欄名應該統一用哪一個？
5. **功能項目列「全選」的行為**
   - 現況：文字表的「全選」欄在功能項目列標「—」，只描述模組層全選。截圖卻在每個功能項目列都放了「全選」勾選框，模組層勾選框則放在模組名稱左側。
   - 要問：功能項目列的全選怎麼運作？模組只勾了部分時，模組勾選框要怎麼顯示？
6. **列表右上角 4 個 icon 的用途**
   - 現況：文字只寫「編輯」「新增」兩個按鈕，截圖卻有 ＋、⇅、垃圾桶、筆四個 icon，文字也沒寫刪除按鈕在哪裡。
   - 要問：⇅ 是不是調整角色順序？如果是，排序規則是什麼？刪除是不是按垃圾桶刪除目前分頁的角色？
7. **編輯模式的呈現方式**
   - 現況：文字寫「編輯」進入編輯模式，底部的儲存、取消「編輯模式下顯示」，聽起來像在列表頁原地編輯。但新增是一個獨立頁面「新增角色」，而且沒有編輯畫面的截圖。
   - 要問：編輯是在原分頁原地切換，還是進入「編輯角色」頁？儲存或取消後要停在哪裡？
8. **「列印／匯出」是否帶動「檢視」**
   - 現況：權限相依規則只寫「新增／編輯」或「刪除」會帶動「檢視」，沒有提到「列印／匯出」。
   - 要問：勾「列印／匯出」時要不要也自動勾「檢視」？已勾其他權限時取消「檢視」，要怎麼處理？
9. **角色名稱長度與比對規則**
   - 現況：只規定不可重名，沒有定長度上限，也沒說前後空白和大小寫怎麼比對。
   - 要問：長度上限是多少？前後空白和英文大小寫要怎麼比對？
10. **稽核日誌保存期限**
    - 現況：Story 4 和非功能需求都寫「待 PM 確認合規要求」，建議至少 6 個月。
    - 要問：最終保存期限是多久？由誰確認？
11. **刪除確認 Dialog 的內容**
    - 現況：只寫「顯示二次確認 Dialog」，沒有文案、按鈕和截圖。
    - 要問：刪除確認 Dialog 的文案和按鈕是什麼？
