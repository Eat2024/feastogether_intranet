## 概述

- 角色管理讓管理員自行定義後台角色，並勾選每個角色可以對哪些功能做哪些動作。
- 角色的名稱和數量不限。只有「系統管理員」（Admin）由系統固定，全部功能全開，不可異動。
- 角色建立後，到「帳號管理」把角色指派給同仁，同仁就依角色的權限使用後台。指派角色不屬於本功能。
- 前台的投票、報名資格由資格名單決定，和角色無關。
- 對應的專案目標是「把 IT 從年度維運中移除」：
  - 同仁關係部要新增承辦人類型，或調整某類承辦人能用的功能時，可以自行在本功能完成，不需要工程師改程式或資料庫。
  - 權限調整要立即生效。
- 選單位置：後台選單「權限管理 / 角色管理」，麵包屑是「首頁 / 權限管理 / 角色管理」。
  - 本功能只做 PC 版，不做手機版。
  - 同一層還有「帳號管理」，另有獨立 PRD。
  - 同一層的「操作紀錄」畫面可以最後開發，但資料要優先同步寫入。
- 本功能有三個畫面：
  - 列表頁：依角色分頁，唯讀。
  - 編輯頁：新增和編輯共用同一頁。
  - 排序／刪除頁。
- ClickUp 頁面上的開發提醒（原文）：
  - 系統共用，拿程式 不出畫面，央廚系統延用
  - 匯出文字檔前，請先處理好字串內的特殊控制字元
  - 留意 SQL Injection、跳脫字元風險
  - OWASP Top 10 漏洞須修復

### 使用者

| 使用者 | 身分由什麼決定 | 帳號來源 | 主要行為 |
| --- | --- | --- | --- |
| 管理員（具本功能權限者，例如系統管理員） | 帳號管理指派的角色，一個帳號一個角色 | 從 HR 系統經 OAuth 同步。上線時的第一位系統管理員由 PG 建立 | 新增、編輯、刪除角色；勾選角色的功能權限；調整角色順序、修改角色名稱 |

### Toast

| Toast | 樣式 | 文案 | 出現時機 |
| --- | --- | --- | --- |
| 儲存成功 | 綠色 | 「儲存成功」 | 編輯頁或排序／刪除頁儲存成功、回到列表頁後 |

| 角色仍有帳號 | 紅色 | 「該角色目前有 {N} 個帳號，請先至帳號管理重新指派後再刪除_{錯誤代碼}」 | 列表頁按刪除時，帳號數 ≥ 1；或排序／刪除頁儲存時，某個刪除列已被指派帳號 |

Toast 樣式規則：

- 元件與顏色：
  - 使用 MUI Alert 實心樣式（`variant="filled"`）。
  - 錯誤是紅色 `#D32F2F`，成功是綠色 `#2E7D32`，文字和圖示是白色。
  - 圖示在左側：錯誤是圓圈驚嘆號，成功是圓圈打勾。圓角 4px。
- 文字：
  - 文案放在 {Title} 位置，只寫一句話；需要補充時才加第二行 {Description}。
  - 文案過長時自動換行，不截斷。
- 位置：
  - PC 和手機都固定在畫面右上角、頁首下方，靠右對齊，捲動時不移動。
  - PC 版寬度隨文字長度，最寬 600px；手機版左右各留 16px。
- 顯示行為：
  - 5 秒後自動消失，沒有關閉（X）按鈕。
  - 畫面上同時只顯示 1 則。新的取代舊的，並從新的出現時重新計算 5 秒。
  - 不加遮罩，不鎖住畫面。
- 不跳 toast 的情況：
  - 勾選和拖曳本身就有畫面回饋。
  - 取消和刪除的確認改用提醒視窗。
  - 欄位驗證錯誤用紅框顯示。
  - 「該角色目前有 N 個帳號」只在滑過 ㉕ 時以提示顯示。
  - 沒有權限時，直接不顯示對應的選單或按鈕。

## 功能需求

### 列表的查看

- **ROLE-01**：列表頁依排序／刪除頁設定的順序顯示角色分頁，格式是「{角色名稱} ({人數})」。系統管理員固定在第一個，進入頁面時預設停在系統管理員分頁。
- **ROLE-02**：分頁人數等於指派到該角色的帳號數，包含啟用、停用和草稿帳號。
- **ROLE-03**：每個分頁依功能項目清單列出功能模組和功能項目，唯讀顯示該角色的權限。有權限的動作顯示藍色勾；該功能項目沒有的動作永遠留白。
- **ROLE-04**：系統管理員分頁的每個功能項目，所有可用動作都打勾，而且不顯示 ④ 刪除、⑤ 編輯。
- **ROLE-05**：功能模組可以收合和展開。初始狀態下，權限管理、投票設定、報名設定展開；報名管理和公告、條款與通知管理收合。
- **ROLE-06**：角色沒有任何權限時，分頁仍會顯示，權限欄全部留白。

### 新增、編輯與儲存角色

- **ROLE-07**：按列表頁 ② 新增會開啟空白的編輯頁，標題是「新增角色」，⑩ 空白，所有權限都不勾。按某個角色分頁的 ⑤ 編輯，會開啟該角色的編輯頁，標題是「編輯角色」。
- **ROLE-08**：⑩ 角色名稱的規則：
  - 必填，最長 20 字，第 21 個字元無法輸入。
  - 不可和其他角色同名，比對時忽略前後空白、英文不分大小寫。
  - 未填時顯示「此欄位為必填」，重名時顯示「角色名稱已存在」。
  - 欄位錯誤時不存檔，留在編輯頁，⑩ 顯示紅框，並把畫面帶到 ⑩。
- **ROLE-09**：權限全部不勾也可以儲存。
- **ROLE-10**：儲存成功時：
  - 回到列表頁，停在該角色分頁，跳出綠色 toast「儲存成功」。
  - 新角色排在順序最後，人數是 0。
  - 新角色出現在帳號管理的角色選單，可以指派給帳號。
- **ROLE-11**：已有角色的權限改變後，該角色的所有帳號在下一次操作時就依新權限判斷，不需要重新登入。
- **ROLE-12**：按 ⑳ 取消時，一律先跳〈提醒視窗：取消〉：
  - 選「是」：不存檔，回到列表頁，留下稽核紀錄。
  - 選「否」：關閉提醒，留在原頁面，已填的內容保留。
- **ROLE-13**：系統管理員角色不可進入編輯頁。後端拒絕任何修改系統管理員角色的請求，例如直接用 API 送出也不寫入。
- **ROLE-14**：存檔失敗、逾時或網路中斷時：
  - 不存檔，跳出紅色 toast「儲存失敗，請稍後再試_{錯誤代碼}」。
  - 已填和已勾選的內容保留，可以直接再按一次儲存。
- **ROLE-15**：併發與重送：
  - 兩位管理員同時編輯同一個角色時，以後儲存的人為準，兩筆稽核紀錄都保留。
  - 兩位管理員同時新增同名角色時，先儲存的成立，後儲存的顯示「角色名稱已存在」。
  - 連按儲存只存一次，也只留一筆紀錄。
  - 網路恢復後重試，只建立一個角色、留一筆紀錄。

### 權限勾選

- **ROLE-16**：功能項目沒有的動作，不顯示勾選框。例如帳號管理沒有刪除和匯出。
- **ROLE-17**：⑭ 列全選：
  - 勾選時勾選該功能項目的全部動作，取消時全部取消。
  - 該列所有動作都勾選時，⑭ 顯示勾選，否則不勾。
- **ROLE-18**：⑫ 模組全選：
  - 勾選時勾選該模組下所有功能項目的全部動作，取消時全部取消。
  - 模組下全部動作都勾選時顯示勾選，全部沒勾時不勾，其他情況顯示部分勾選（－）。
  - 部分勾選時按一下，會變成全部勾選。
- **ROLE-19**：勾選新增、修改、刪除或匯出任一項時，同一列的「查看」自動勾選。
- **ROLE-20**：勾選只改變畫面，按 ㉑ 儲存才存檔。

### 刪除角色（列表頁）

- **ROLE-21**：在某個角色分頁按 ④ 刪除時，系統先算出該角色的帳號數（包含啟用、停用和草稿帳號）：
  - 帳號數 ≥ 1：不跳提醒、不刪除，跳出紅色 toast「該角色目前有 N 個帳號，請先至帳號管理重新指派後再刪除_{錯誤代碼}」。
  - 帳號數 = 0：跳出〈提醒視窗：刪除角色〉。
- **ROLE-22**：在提醒視窗按「確認刪除」時：
  - 刪除角色和它的權限設定，該分頁消失，畫面停在第一個分頁。
  - 留下稽核紀錄，記錄刪除前的名稱和權限。角色刪除後，稽核紀錄仍保留。
  - 按「取消」時，關閉提醒、維持原畫面。
- **ROLE-23**：按「確認刪除」的瞬間，系統再檢查一次帳號數。如果帳號管理剛好在這時指派了帳號，就不刪除，並依 ROLE-21 跳出「角色仍有帳號」toast。
- **ROLE-24**：已經刪除的角色不會再刪一次，也不會因為找不到資料而報錯。逾時或網路中斷時不刪除，跳出紅色 toast「網路連線異常，請稍後再試_{錯誤代碼}」，可以重試。

### 排序與刪除角色（排序／刪除頁）

- **ROLE-25**：按列表頁 ③ 排序進入排序／刪除頁，依目前順序列出每個角色的名稱、人數和刪除鈕。
- **ROLE-26**：拖曳 ㉒ 調整順序，放開後立即重排。系統管理員固定在第一列，不可拖曳，其他角色也不能拖到它上方。
- **ROLE-27**：可以在 ㉓ 直接修改角色名稱，規則和 ⑩ 相同。系統管理員這一列唯讀。
- **ROLE-28**：㉕ 刪除鈕的規則：
  - 人數為 0 時才可按。人數大於 0 時是淺灰色、不可按，滑過時提示「該角色目前有 N 個帳號，請先至帳號管理重新指派」。
  - 系統管理員一律不可按。
  - 按下後該列從畫面移除，要儲存才真正刪除。
- **ROLE-29**：按 ㉗ 儲存時：
  - 有刪除列：先跳〈提醒視窗：刪除角色〉，按「確認刪除」後才寫入。
  - 整頁一次寫入，不會只存一半。
  - 成功時回到列表頁，跳出綠色 toast「儲存成功」。
  - 列表頁 ① 和帳號管理的分頁依新順序顯示。
  - 改名後的名稱同步到帳號管理的分頁、權限欄和角色選單。
- **ROLE-30**：儲存不成立時，整頁不存檔：
  - 名稱未填或重名：該列紅框，顯示「此欄位為必填」或「角色名稱已存在」。
  - 某個刪除列在儲存當下已被指派帳號：跳出「角色仍有帳號」紅色 toast，該列恢復顯示。
  - 存檔失敗、逾時或網路中斷：跳出紅色 toast「儲存失敗，請稍後再試_{錯誤代碼}」，畫面維持，可以重試。
- **ROLE-31**：按 ㉖ 取消時，一律先跳〈提醒視窗：取消〉：
  - 選「是」：不存檔，本次的排序、改名、刪除全部還原，回到列表頁。
  - 選「否」：留在本頁，已調整的內容保留。
- **ROLE-32**：兩位管理員同時調整順序時，以後儲存的人為準，兩筆紀錄都保留。連按儲存只存一次。

### 權限判斷與資料範圍

- **ROLE-33**：沒有本功能的查看權限時，選單不出現「角色管理」。缺少某個動作權限時，對應的按鈕不顯示（見〈本功能的權限矩陣〉）。
- **ROLE-34**：後端每一次處理後台請求，都依帳號目前角色的權限判斷，不能只看登入當下的權限。權限改變後不需要登出。
- **ROLE-35**：角色有「資料範圍」設定，二選一：
  - 「全集團」：看得到全部同仁的資料。
  - 「只看自己管理的部門」：範圍是 HR 回傳的管理部門，可以有多個，部門清單不在後台維護。
  - 系統管理員固定為「全集團」。
- **ROLE-36**：資料範圍只用在有同仁資料的查詢，目前只有「報名名單查詢」。其他功能只要有查看權限，就看得到全部。
- **ROLE-37**：系統只看角色的資料範圍設定：
  - 同仁在 HR 是不是主管，不影響「全集團」角色的範圍。
  - 角色設成「只看自己管理的部門」、但 HR 回傳的管理部門是空的時候，查無資料，畫面顯示「僅顯示您管理的部門」。
- **ROLE-38**：角色不影響前台投票和報名資格。即使某角色被取消「投票活動設定」的權限，只要同仁在投票資格名單中，仍可以在前台投票，報名也一樣。

### 稽核紀錄

- **ROLE-39**：每次儲存、排序、改名、刪除、取消都各留一筆稽核紀錄，不覆蓋。在排序／刪除頁，排序、每個改名、每個刪除也各留一筆。
- **ROLE-40**：每筆稽核紀錄包含：
  - 操作者（員工編號與姓名）
  - 行為
  - 時間（台灣時間，精確到秒）
  - 角色名稱
  - 異動前後的權限差異
- **ROLE-41**：稽核紀錄在「操作紀錄」功能查詢，唯讀，不可刪除。

### 系統初始化與非功能需求

- **ROLE-42**：系統初始化時建立系統管理員（Admin）角色，固定存在、全部動作全開，不可修改或刪除。上線時的第一位 Admin 帳號由 PG 建立。
- **ROLE-43**：PG 要為所有 API 呼叫設定 timeout，重試時不可重複寫入。
- **ROLE-44**：錯誤代碼：
  - PG 設計錯誤代碼，並提供代碼表（code 和對應的 msg）。
  - 所有紅色 toast 的文案結尾加上「_{錯誤代碼}」。
- **ROLE-45**：效能壓測要涵蓋兩種情境，每種都持續操作 30 分鐘以上：
  - 3,000 人同時湧入。
  - 陸續登入到 3,000 人，期間沒有人登出。
- **ROLE-46**：兩種情境都要達到以下標準：
  - 按「儲存」或「刪除」後，1 秒內完成，並更新列表頁的分頁、人數和權限勾號（這個時間是專案管理部的建議，待資訊部確認）。
  - 成功率達 99.5% 以上。
  - 壓測結束後，角色的權限、順序和稽核紀錄筆數都和實際操作相符。
- **ROLE-47**：只做 PC 版，不做 RWD，要支援 14 吋、22 吋和 27 吋螢幕。
- **ROLE-48**：安全性：
  - 所有權限變更都由後端再驗證一次，前端勾選只影響畫面。
  - 後端一律拒絕修改或刪除管理員角色。
  - 匯出文字檔前，先處理字串內的特殊控制字元。
  - 防範 SQL Injection 和跳脫字元風險。
  - 修復 OWASP Top 10 漏洞。
