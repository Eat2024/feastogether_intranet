## 概述

- **解決什麼**：
  - 具投票資格的同仁在投票頁閱讀投票說明、查看候選地點的行程，再依國內、國外各自的可投票數點選地點投票。點選即完成投票，不需另按送出；截止前可以不限次數改票。
  - 同仁關係部直接在投票頁查看各地點得票數，不需再等 IT 隔日提供票數。這對應專案目標「把 IT 從年度維運中移除」。
  - 投票結果只供報名地點參考。截止即開票，系統不做定案，投票與報名之間沒有系統關聯。
- **使用者**（屬員工端／前台）：
  - 同仁：員工編號在該投票活動的投票資格名單中。以手機為主。
  - 管理員（同仁關係部）：有投票頁查看權限，唯讀查看即時得票數。PRD 的 Use Case 以 PC 操作為例。
- **裝置**：
  - 頁面做 RWD。手機以 iPhone 15 Pro、iPhone 15 Pro Max 為主；PC 支援 14 吋、22 吋、27 吋。
  - 設計稿有 PC 版、手機版兩張，都是卡片式排列，沒有序號與票數排序；PC 列表版不採用。
  - Sitemap 標示為「手機 ✓ ／ PC ▲」。
- **進入方式**：
  - 同仁從首頁的投票入口進入。入口卡片屬「S1-01 首頁／活動總覽」PRD，那份 PRD 尚未撰寫。
  - PRD 也描述了「直接開網址」時的呈現。
- **Sitemap**：S4-投票設定（後台選單）底下有「投票活動設定（含名單匯入 & 候選行程）」和「投票頁」。投票頁下分「國內」「國外」兩個分頁。
- **一次只顯示一個投票活動**，各活動的票數分開計算。

### 本次範圍與非範圍

本次範圍：

- 投票頁：活動名稱、期間、倒數、說明文案。
- 國內／國外分頁與專區篩選。
- 候選地點清單、查看行程。
- 點選投票、再點一次取消投票（點選即生效）、截止前改票。
- 得票數顯示（依揭露即時票數設定）與開票結果。

| 不做 | 原因 |
|---|---|
| 開票定案、採用標記 | 系統不做定案動作，截止即為開票；截止後只顯示得票數 |
| 改票次數限制 | 不限次數，由截止時間控制 |
| 管理員代同仁投票 | 投票為個人意願，沒有代投需求 |
| 投票提醒通知 | 本功能不發通知；開放通知由同仁關係部在平台外發送 |
| 投票頁匯出 Excel | 投票結果只在投票頁查看，不提供下載；後台名單下載也不帶出投票結果 |
| 首頁投票入口卡片 | 屬「首頁／活動總覽」，另寫 PRD |
| 送出流程（送出按鈕、取消鍵、提醒視窗、未投滿二次確認） | 點選地點即完成投票，未投滿也有效 |
| 行程瀏覽期 | 不設；候選地點與行程隨投票開始時間一起開放，沒有提前預覽 |
| 頁首「已儲存」、自動儲存 | 投票頁不做 |

## 依賴的後台設定

投票頁顯示和判斷所用的資料，都由「投票活動設定」在管理員儲存並發佈時寫入，投票資格名單則在匯入成功時寫入。下表「設定端規則」一欄摘自《投票活動設定 PRD》v0.78，只供對照，規則以該份 PRD 為準。

| 設定欄位 | 設定端規則（摘要） | 投票頁用途 |
|---|---|---|
| 發佈狀態（草稿／已發佈／停用） | 停用由設定 ⑰ 啟用開關控制，可重新啟用 | 只有已發佈的活動能進入投票頁；停用後顯示「本投票已停用」 |
| 投票狀態（空白／投票中／已截止） | 依發佈狀態、設定 ⑳、設定 ㉑ 與現在時間判定 | 決定頁面呈現：沒有進行中的投票、投票期或已截止 |
| 設定 ⑰ 啟用 | 關閉＝停用，已投的票失效；打開並儲存＝重新啟用，失效的票不恢復 | 停用呈現、ST-01 狀態「已失效」 |
| 設定 ⑲ 投票名稱 | 最長 20 字 | ①／⑪ 投票名稱 |
| 設定 ⑳ 投票開始時間 | YYYY/MM/DD HH:mm；投票開始後唯讀 | ②／⑫ 投票期間；投票期起點；候選地點與行程在此時間一起開放 |
| 設定 ㉑ 投票截止時間 | 投票中仍可修改：改早＝提前結束，往後延＝延長 | ②／⑫ 投票期間、③／⑬ 倒數、截止判定 |
| 設定 ㉒ 國內可投票數 | 整數 0～99；0＝不開放國內投票 | 國內分頁是否顯示、國內票數上限、⑤／⑮ 分頁標籤 |
| 設定 ㉓ 國外可投票數 | 整數 0～99；0＝不開放國外投票（國內＋國外至少 1） | 國外分頁是否顯示、國外票數上限、⑤／⑮ 分頁標籤 |
| 設定 ㉔ 投票說明文案 | 富文字，不提供底線與表格，上限 1,000 字 | ④／⑭ 原樣顯示 |
| 設定 ㉕ 揭露即時票數 | 勾選框，預設不勾；投票開始後唯讀 | ⑧／⑱ 在投票期是否顯示 |
| 設定 ㉚ 國內／國外分頁 | 候選地點分屬國內或國外 | 地點出現在哪個分頁 |
| 設定 ㉞ 序號 | 系統產生，1 起算；可拖曳排序（投票開始後不可用） | 候選地點的排列順序；專區篩選選項的順序 |
| 設定 ㉟ 專區 | 選填，最長 10 字，例：25,000 專區、東南亞 | ⑥／⑯ 專區篩選選項 |
| 設定 ㊱ 候選地點 | 最長 30 字 | ⑦／⑰ 地點名稱；toast 文案中的 {地點名稱} |
| 設定 ㊲ 行程類型、㊳ 行程內容 | 連結網址（https://）或上傳檔案（PDF、Excel、Word、JPG、PNG，單檔 10 MB）；㊳ 空白時同仁端看不到該地點 | ⑨／⑲ 查看行程；沒有行程的地點整個不顯示 |
| 投票資格名單（匯入） | 以員工編號為鍵；L 欄參加資格「不符合」的列略過不匯入；名單內＝有投票資格；投票中不可重新匯入 | 判斷有無投票資格；名單人數是票佔比的分母 |

投票頁也會回寫後台：每次點選投票或取消投票，後台投票活動設定列表頁的投票率即時重新計算。

## 畫面與狀態

### 版面（PC 版／手機版）

由上到下的元件：

1. 頁首（依截圖，僅 PC 版）：
   - 左側為麵包屑「首頁 / 選單第1層 / 選單第2層」。
   - 右側依序為日期時間（例：2026/05/12 08:59）、圓形頭像（縮寫「OP」）、姓名（John Doue）與員工編號（11005096），以及下拉箭頭。
   - 手機版截圖沒有畫頁首。PRD 正文沒有定義頁首。
2. ①／⑪ 投票名稱：大字標題，例：「2026 下半年國外旅遊（特別加開）投票」。
3. ②／⑫ 投票期間：前面有日曆圖示，例：「2026/03/02 10:00 ～ 03/09 18:00」。
4. ③／⑬ 倒數：前面有時鐘圖示，標示「現正倒數」。天、時、分、秒各自放在紅底白字方塊中，格式為「3 天 03:24:59」。下方有分隔線（依截圖）。
5. ④／⑭ 投票說明文案：位在倒數下方、分頁上方。設計稿上的條列文字只是範例。
6. ⑤／⑮ 國內／國外分頁：選中的分頁為藍字加藍色底線，未選的分頁為灰字（依截圖）。
7. ⑥／⑯ 專區篩選：晶片列，選中的晶片為深色實心，其他為外框樣式（依截圖）。手機版可橫向捲動。
8. 候選地點卡片清單：每張卡片包含：
   - ⑦／⑰ 地點名稱（粗體）。
   - ⑧／⑱ 進度條，下方是「N票」。
   - ⑨／⑲「查看行程」按鈕（文件圖示，外框樣式）。
   - ⑩／⑳ 投票按鈕（大拇哥圖示）。
   - 按鈕位置（依截圖）：PC 版在卡片右側；手機版在得票數下方，兩顆按鈕等寬並排。

| 載入中 | 頁面載入中，或點選後正在寫入 | 顯示載入狀態，畫面不可空白；寫入中該地點的 ⑩／⑳ 不可再按 | — |

### 分頁內狀態

| 狀態 | 判定 | 畫面顯示 |
|---|---|---|
| 分頁不顯示 | 該類可投票數（設定 ㉒／㉓）為 0 | 不顯示該分頁 |
| 目前沒有候選地點 | 分頁內沒有可顯示的地點：沒有地點，或所有地點都沒設定行程 | 「目前沒有候選地點」 |
| 地點數少於可投票數 | 例：可投 3 票，但只有 2 個地點 | 照常顯示；同仁最多只能投到地點數，因為同一地點限 1 票 |
| 不顯示專區篩選 | 分頁內所有地點都沒有專區 | 不顯示 ⑥／⑯ |

### 同仁投票狀態（ST-01）

| 狀態 | 判定規則 | 前台呈現 | 系統動作 |
|---|---|---|---|
| 1 無投票資格 | 不在投票資格名單 | 入口可見但不可用 | — |
| 2 未投票 | 在名單內，沒有已投的地點 | 所有地點都是「我要投票」 | — |
| 3 已投票 | 至少投了 1 個地點，且在投票期 | 已投的地點顯示「已投票」，可再點選改票 | 每次點選即寫入，並即時更新得票數 |
| 4 已鎖定 | 至少投了 1 個地點，且已截止 | 顯示已投內容，不可修改 | 以此內容計入開票結果 |
| 5 已失效 | 投票活動被停用 | 顯示「本投票已停用」，不可投票、不可改票 | 紀錄保留，不計入得票數；重新啟用後不恢復，須重新投票 |

狀態流轉：2 未投票 → 3 已投票（投票期內可改票）→ 4 已鎖定（截止後）。任何有資格的狀態在活動被停用時都會進入 5 已失效。

### 投票按鈕的畫面變化

以下以國外可投 2 票為例：

| 操作 | ⑩／⑳ 按鈕 | 該地點 ⑧／⑱ 得票數 | ⑤／⑮ 分頁 | 回饋 |
|---|---|---|---|---|
| 初始 | 「我要投票」無色底 | N 票 | 已投 1，尚有 1 票 | 無 |
| 點「我要投票」 | 「已投票」藍色底 | N+1 票 | 已投 2，尚有 0 票 | 綠色 toast「已投給「{地點名稱}」」 |
| 點「已投票」 | 「我要投票」無色底 | N 票 | 已投 1，尚有 1 票 | 綠色 toast「已取消「{地點名稱}」的投票」 |
| 尚有 0 票時點其他地點的「我要投票」 | 不變 | 不變 | 不變 | 不跳 toast，改跳提醒視窗「票數已投滿」 |

- 每次只有被點的地點會變化，其他地點的按鈕與得票數都不變。
- 先投票再取消後，得票數、已投數和剩餘票數都回到初始值，不會重複累加或扣減。

### 提醒視窗：票數已投滿

依截圖，版型由上到下是：橘色警示三角圖示、粗體標題、灰字文案、整寬藍底按鈕，外框為白底圓角卡片。

| 項目 | 內容 |
|---|---|
| 觸發 | 該分頁已投滿，又點了其他地點的「我要投票」 |
| 標題 | 「票數已投滿」 |
| 文案 | 「{國內／國外}已選滿{可投票數}票，請先取消其中1票，才能再選其他行程」，數字一律用阿拉伯數字。例：「國外已選滿2票，請先取消其中1票，才能再選其他行程」 |
| 按鈕 | 「我知道了」：點了關閉視窗並回到原畫面。被點的地點維持「我要投票」無色底，得票數不變 |

### toast

| toast | 樣式 | 文案 | 出現時機 |
|---|---|---|---|
| 投票成功 | 綠色 | 「已投給「{地點名稱}」」，例：「已投給「馬來西亞沙巴 5 日」」 | 點「我要投票」後寫入成功，按鈕同時變為「已投票」 |
| 取消投票成功 | 綠色 | 「已取消「{地點名稱}」的投票」 | 點「已投票」後寫入成功，按鈕同時變回「我要投票」 |
| 投票已截止 | 紅色 | 「投票已截止_{錯誤代碼}」 | 點選時伺服器時間已到截止時間；不寫入，頁面切換為已截止的呈現 |
| 本投票已停用 | 紅色 | 「本投票已停用_{錯誤代碼}」 | 點選時活動已被停用；不寫入，頁面切換為停用的呈現 |
| 網路連線異常 | 紅色 | 「網路連線異常，請稍後再試_{錯誤代碼}」 | 點選時網路中斷或 API 逾時；不寫入，按鈕回到點選前的狀態，可再點一次重試 |

toast 的樣式規則：

- 元件與顏色：
  - 使用 MUI Alert 的實心樣式（`variant="filled"`）。
  - 錯誤為紅色 `#D32F2F`，成功為綠色 `#2E7D32`。文字與圖示都是白色 `#FFFFFF`。
  - 圖示在左側：錯誤用圓圈驚嘆號，成功用圓圈打勾。
- 文字：
  - 文案放在 {Title} 位置，只有一句，不使用 {Description} 第二行。
  - 文案過長時自動換行，不截斷。
  - 紅色 toast 的文案最後一律加「_{錯誤代碼}」。
- 外觀：圓角 4px。
- 顯示與關閉：出現 5 秒後自動消失，不提供關閉（X）按鈕。
- 位置：
  - PC 版與手機版都固定在畫面右上角、頁首下方，靠右對齊。
  - 頁面捲動時不移動。
  - PRD 附的位置示意圖裡有「已儲存」和淺色底的 toast，這兩者都不採用。
- 寬度：PC 版依文字長度，最寬 600px；手機版左右各留 16px，其餘滿版。
- 同時多則：畫面上只顯示 1 則。新的 toast 取代舊的，並從新的出現時重新計算 5 秒。例：10:00:00 跳出一則，10:00:02 又跳一則，畫面只留新的那則，10:00:07 消失。
- 不遮擋操作：不加遮罩、不鎖畫面。

以下情況不跳 toast：

- 已投滿：改用提醒視窗。
- 頁面狀態直接顯示在頁面上：「您目前不具備本次投票資格」「目前沒有進行中的投票」「目前沒有候選地點」，以及停用後的「本投票已停用」頁面。

### 得票數顯示

- **VOTE-PAGE-27**：得票數＝目前投了該地點的同仁人數。取消投票即扣除；停用時失效的票不計。畫面顯示進度條和「N票」，不顯示百分比。
- **VOTE-PAGE-28**：進度條的長度與顏色：
  - 長度＝該地點得票數 ÷ 投票資格名單人數，最高 100%，與該分頁每人可投幾票無關。
  - 長度四捨五入到整數位後，就是用來判斷顏色的票佔比：85% 以上為橘色；50% 以上、未達 85% 為藍色；未達 50% 為深灰色。剛好 50% 或 85% 時歸入較高的一級。
  - 顏色只依票佔比決定，與同仁自己是否投了該地點無關。得票數文字的顏色不隨投票狀態改變。
  - 例（UC-08-01）：名單 2,000 人時，1,690 票＝84.5%，四捨五入為 85%，顯示橘色；990 票＝49.5%，四捨五入為 50%，顯示藍色；989 票＝49.45%，四捨五入為 49%，顯示深灰色。
- **VOTE-PAGE-29**：得票數的顯示時機依設定 ㉕：
  - 有勾選：投票期和截止後都顯示 ⑧／⑱。

- **VOTE-PAGE-30**：同仁自己點選後，得票數立即更新；其他同仁的投票，要重新整理後才會反映。

## 業務規則與驗證

### 登入、身分與資格

登入由公司的 OAuth server（feastogether_oauth）負責，這一節和它直接相關。以下只記 PRD 寫到的事實。

- **帳號來源**：同仁與管理員的帳號都由 HR 系統同步。依《投票活動設定 PRD》背景資料：
  - 每日 05:00 同步一次。
  - 員工編號是每位同仁必有的唯一識別。
  - 信箱可為空。
- **身分識別鍵是員工編號**：
  - 投票資格以「員工編號是否在該活動的投票資格名單中」判斷。
  - 稽核紀錄也記員工編號。
  - PC 版頁首（依截圖）顯示登入者的姓名與員工編號。
- **能登入不等於有投票資格**：UC-05 的前置資料是「同仁帳號存在、不在名單」，結果是看得到入口但不可用。可見同仁可以登入平台，但不一定能投票。
- **資格依活動而定**：
  - 每個投票活動各有一份名單。
  - 投票資格不靠角色，只靠名單。
  - 資料不依部門限縮，所有人看到的地點、行程、說明文案都相同；有揭露時，看到的得票數也相同。
- **管理員權限靠角色**：
  - Admin 角色由系統固定，全部功能全開。
  - 其他角色由後台彈性設定，名稱與數量不限，在角色管理畫面勾選權限。
  - Admin 在帳號管理指派角色給管理員。
  - 管理員的角色在初次登入時由 PG 給予。《投票活動設定 PRD》另註明不在平台上建立。
  - 角色在投票頁只控制「查看」：唯讀看即時得票數。
- **管理員與名單互相獨立**：管理員不在名單內也可以進入投票頁，但不能投票。
- **時間判定**：期間判定和倒數都以伺服器時間（台灣時間）為準。
- **壓測情境**：包含「陸續登入至 3,000 人，期間沒有人登出」，表示登入與 session 都在壓測範圍內。
- **PRD 沒有寫**：同仁如何登入（帳密、SSO 或 OAuth）、session 時效、未登入或登入逾時時投票頁的行為。見〈待釐清問題〉。

### 票數限制

- 國內、國外分開計算，各自的上限是設定 ㉒、設定 ㉓，範圍 0～99；0 表示不開放該分頁。
- 同一地點每人限投 1 票。
- 能否再投：該分頁已投數必須小於可投票數。例：國外可投 2 票時，已投 0 票或 1 票都還能投；已投 2 票就不能再投，點第 3 個地點會跳「票數已投滿」。
- 剩餘票數＝可投票數－已投數，顯示在 ⑤／⑮ 分頁標籤上。
- 不必投滿，未投滿的票照樣有效。

### 改票與撤票

- 截止前可以隨時改票，不限次數。再點一次「已投票」即取消（撤票）。
- 沒有送出、確認、取消鍵，也沒有「未送出」的狀態。
- 截止後已投內容鎖定，以截止當下的內容開票。
- 設計稿說明文案中的「送出後即完成投票，每人限投一次」只是範例，與改票規則不符。實際文案由同仁關係部在設定 ㉔ 改寫，例：「送出後，截止前都可以隨時回來換票；以截止當下的選擇為準。」

### 時間與期間

| 期間 | 時間點 | 投票頁行為 |
|---|---|---|
| 候選行程建置期 | 現在 ＜ 投票開始時間 | 同仁看不到（沒有行程瀏覽期，也沒有提前預覽） |
| 投票期 | 投票開始時間 ≦ 現在 ＜ 投票截止時間 | 可投票，可不限次數改票；得票數依揭露設定顯示 |
| 開票期 | 現在 ≧ 投票截止時間 | 唯讀，顯示已投內容與得票數 |

- 投票狀態（ST-02，定稿於《投票活動設定 PRD》）：
  - 空白：未發佈，或已發佈但現在 ＜ 投票開始時間。
  - 投票中：已發佈，且投票開始時間 ≦ 現在 ＜ 投票截止時間。
  - 已截止：已發佈，且現在 ≧ 投票截止時間。
- 投票中，管理員只能修改投票截止時間：改早即提前結束，往後延即延長。依設定端背景資料，此時名單與候選地點都不能再匯入或修改。
- 開票不需要排程，期間依伺服器時間即時判定。

### 停用

- 停用後，已投的票失效：紀錄保留，但不計入得票數與投票率。
- 重新啟用後，失效的票不恢復，同仁須重新投票。

### 確認流程與回饋

- 沒有確認流程。唯一的阻擋是已投滿時跳的「票數已投滿」提醒視窗。
- 成功與失敗都以 toast 回饋：成功為綠色，失敗為紅色並帶錯誤代碼。頁面層級的狀態直接顯示在頁面上。

### 開票與報名

- 截止即開票，不做定案，也不顯示採用標記，只顯示得票數。
- 實際開團地點由同仁關係部在「報名行程與梯次管理」建立，同仁在報名頁的「選擇報名行程」查看。投票與報名之間沒有系統關聯。
- 每位同仁投了哪裡，系統不提供。

## 待釐清問題

1. **同仁如何登入投票頁**
   - 現況：PRD 只寫帳號由 HR 系統同步，壓測情境有「陸續登入至 3,000 人」，但沒寫登入方式（帳密、公司 SSO 或 OAuth），也沒寫登入後如何取得員工編號、session 多久過期。
   - 要問：投票頁（以及整個旅遊平台前台）是否透過本 OAuth server 登入？登入後以哪個欄位對應員工編號？session 時效多長？
2. **未登入或 session 過期時的行為**
   - 現況：點選時的錯誤只定義了三種紅色 toast（投票已截止、本投票已停用、網路連線異常），沒有涵蓋未登入或登入逾時。
   - 要問：session 過期後點「我要投票」，或未登入直接開投票頁網址時，要導向登入頁、跳 toast，還是其他處理？已投的狀態如何保留？
3. **用測試帳號預覽投票頁，與頁面可見條件互相衝突**
   - 現況：
     - 《投票活動設定 PRD》Q-23 決議不做預覽，改為「發佈前以測試帳號加入名單，實際登入投票頁確認」。
     - 但本 PRD 規定，草稿或未到投票開始時間時一律顯示「目前沒有進行中的投票」；投票開始後名單又不能再匯入。
     - 測試帳號要能通過名單匯入的員工編號檢查，就必須是 HR 同步過來的帳號；它也會被算進名單人數（票佔比的分母）。
   - 要問：
     - 發佈前要怎麼實際看到投票頁？
     - 測試帳號從哪裡來（HR 是否提供測試員工編號）？
     - 測試帳號的票和名單人數是否要排除？
4. **無資格、停用時「入口可見但不可用」的實際呈現**
   - 現況：
     - 3.4 節寫「看得到入口，點了顯示『您目前不具備本次投票資格』」。
     - 7 章寫「入口可見但不可用」，第 12 章又把它列為直接顯示在頁面上的狀態。
     - 停用時也是「入口可見但不可用」，同時投票頁顯示「本投票已停用」。
   - 要問：
     - 訊息是顯示在首頁入口，還是點進投票頁後顯示？
     - 不在名單的同仁直接開網址時看到什麼？
     - 同一位同仁既不在名單、活動又已停用或尚未開始時，以哪個訊息優先？
5. **多個活動同時進行時，投票頁顯示哪一個**
   - 現況：Q-12 決議投票頁一次只顯示一個活動，多個入口的呈現留給尚未撰寫的「S1-01 首頁／活動總覽」PRD；正文又提到「直接開網址」。
   - 要問：投票頁網址是否帶有活動識別？同仁同時在兩個活動的名單中時，如何進入各自的投票頁？
6. **管理員也在名單內時，投票期能看到即時得票數**
   - 現況：有查看權限的管理員不受設定 ㉕ 限制，投票期就看得到得票數；PRD 只定義了「不在名單內」的管理員（不能投票）。風險表把「揭露即時票數造成從眾」列為風險。
   - 要問：管理員同時在名單內時，是否照樣可以投票，並在投票期看到其他同仁看不到的得票數？
7. **管理員的「即時同步」與「重新整理才更新」**
   - 現況：〈得票數顯示〉成立條件第 3 點寫管理員「即時同步同仁投票的結果」，但同一節的併發規則和 UC-13 都寫「重新整理後更新」。
   - 要問：管理員畫面是否需要自動更新票數，還是重新整理即可？
8. **得票數文字的顏色**
   - 現況：Q-20 決議「得票數文字顏色不變」。但票數顏色規則圖中，文字顏色跟著進度條分級：藍色級為藍字「30票」，橘色級為深色粗體「3,225票」，深灰級為灰字「25票」。
   - 要問：文字顏色是否依票佔比分級？還是全部同一個顏色，只有進度條變色？
9. **截圖與 PRD 文字不一致（PRD 文字為準，需確認設計稿是否會更新）**
   - 現況（依截圖）：
     - (a) 第 2 張卡片「30票」的進度條長度約兩成，卻是藍色，文字也是藍色。這比較像舊規則「自己投的地點為藍色」，與「依票佔比上色」不符。
     - (b) 投票前後對照圖中，投票後分頁標籤仍是「國外（已投1，尚有1票）」，「30票」也沒有 +1；但 PRD 規定兩者都要即時更新。
     - (c) 專區晶片為「全部 (12)」「25,000 專區 (4)」「東南亞 (3)」「日本 (5)」「歐美 (4)」，各專區加總是 16，不等於 12；設定 ㉟ 每個地點只有一個專區。
     - (d) 千分位不一致：PC 版寫「2725票」，手機版寫「3,225票」，UC-08-01 用「1,690票」。
   - 要問：設計稿與原型是否會依 Q-18、Q-20 修正？得票數是否一律加千分位？
10. **部分地點沒有專區時怎麼篩選**
    - 現況：PRD 只定義「全部地點都沒有專區時不顯示篩選」。
    - 要問：只有部分地點沒填專區時，這些地點是否只出現在「全部」底下？是否需要「其他」選項？

    - 要問：「有可投票數」是指設定值大於 0，還是同仁還有剩餘票數？例如國內已投滿時，是否仍預設停在國內？
