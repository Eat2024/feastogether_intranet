# Spec 016 ticket 拆分草稿

狀態：待使用者確認拆分與依賴，尚未建立新的正式 tickets。

依據：[spec](spec.md)、[plan](plan.md)、[tasks](tasks.md) 及 [contracts](contracts/portal-login.md)。既有 01 規劃票保留原狀，不覆寫、關閉或重新編號。新增實作票預計從 02 起，各票正式建立時狀態為 ready-for-agent，只有 blockers 全部 resolved 才開始。規劃文件已存在，01 的歷史與待環境驗收項目不作為所有實作票的人為阻擋。

本草稿採完整功能切片。除了 02 為實作前的必要小幅整理，每張票都涵蓋該行為所需的 UI／API／worker／測試，不把同一條可驗收流程拆成前後端兩張。共用既有分支整合，個別票驗收不等於可獨立部署。

## 02：共用簽署表單，保持外部簽署行為

**What to build:** 將既有閱讀、聲明、簽名與提交的共用畫面整理為內外部可用的表單，讓後續本人簽署直接沿用；本票外部使用者操作與結果保持原樣。

**Blocked by:** 無，可開始。

**Tasks coverage:** T020；T001/T002 的電子簽工作區與規範檢查；T023 的外部表單回歸部分。

- [ ] 共用表單只負責呈現、簽名狀態及資料轉換，由外部容器負責原 API 與失效處理，不新增 provider framework。
- [ ] 外部閱讀、同意、簽署／拒簽、固定 requestId 重試、防連點與切換文件行為不變。
- [ ] 電子簽內部流程可使用共用表單而不依賴外部 cookie API 或 Email 文案。
- [ ] 前端 lint/build、桌面與窄螢幕外部流程回歸通過；尚無 client 自動測試框架，不虛報自動測試。

## 03：Portal 共用登入回跳與改密碼接續

**What to build:** 員工點帶 redirect_to 的登入連結後，登入或必要改密碼完成即自動抵達目的頁；其他頁面可擴充允許清單共用此能力。

**Blocked by:** 無，可與 02 並行。

**Tasks coverage:** T005–T011；T001/T002 的 Portal 工作區與契約檢查。

- [ ] 集中允許映射初始包含「我的電子簽」；新增測試頁映射不用修改登入或改密碼判斷，映射移除後舊 session 目的地失效。
- [ ] 未登入、已登入、錯誤帳密重試、無參數新登入與非法參數符合契約，POST 不因缺少 query 清掉目的地。
- [ ] 必須改密碼者先完成改密碼；重新點 Email 不能繞過待辦，更新失敗保留目的地，成功及登出正確清除。
- [ ] 一般登入仍回原首頁，目的頁仍檢查權限；既有 iframe/session 銜接可抵達我的電子簽，不改 launch 協定。
- [ ] 保留 Portal 原有工作區修改，PHP 語法、可隔離回跳測試與瀏覽器案例留有結果；環境不可用的驗收明確保留待完成。

## 04：員工從我的電子簽完成閱讀與簽署

**What to build:** 有效登入的員工可直接開啟本人待簽文件、閱讀、同意並簽署；成功後看到已簽結果與更新後的列表，不需 Email OTP。

**Blocked by:** 02 共用簽署表單。

**Tasks coverage:** T014–T016；T012/T013/T018/T019/T021/T023 的開啟、原檔、簽署、權限、狀態及重送部分。

- [ ] 以任一正式支援的員工 session 操作本人指派，沒有 Email 或未點邀請信不影響授權；非本人／外部指派拒絕，未登入及過期拒絕。
- [ ] 正式畫面與 API 完成閱讀、同意、簽名及提交，移除待簽回 Email 提示；換文件重置，pending 防連點，session 失效不自動提交。
- [ ] 後端交易前與鎖內核對本人、期限、狀態、聲明、欄位、PNG 與文件完整性；同 requestId 重送回原結果，併發不建立重複證據。
- [ ] 新內部證據記 internal_session，外部保持原驗證方式；歷史簽章、PDF 及稽核證據不變。
- [ ] 完成結果與列表同步；單元、API／安全測試及桌面／窄螢幕路徑通過。本票不宣稱舊 OTP 切換已完成，整體上線須等 09／10。

## 05：員工拒簽、完成結果與本人副本

**What to build:** 員工可依文件規則拒簽；已簽者能在我的電子簽查看副本產製狀態並下載，不需回邀請信。

**Blocked by:** 04 員工閱讀與簽署。

**Tasks coverage:** T017/T022；T012/T013/T018/T019/T021/T023 的拒簽、副本與完成頁部分。

- [ ] 允許拒簽的文件可完成拒簽及選填原因；不允許者 server 也拒絕，重送不重複寫入，列表同步。
- [ ] 已簽者看到產生中／ready／failed，使用唯讀查詢輪詢；完成、失敗或離開頁面停止輪詢，不重複寫開啟事件。
- [ ] 可下載本人已簽副本，保留完整性檢查與到期後既有存取規則；其他人的副本與未簽者均不可取得。
- [ ] 正常內部流程不含返回 Email 指示；拒簽、下載、期限、失效、跨人與外部共用畫面回歸通過。

## 06：新發起文件的內部 BCC 邀請與可靠結果追蹤

**What to build:** 建立人發起含內部員工的文件後，同一次通知以一封多人的 BCC 邀請寄出，保留逐人投遞結果；混合名單的外部邀請維持逐人專屬連結。

**Blocked by:** 無。可獨立以測試信件驗證，不須等待 Portal 導頁部署。

**Tasks coverage:** T003；T024/T026–T028/T030/T032–T035/T037 的新發起邀請、群寄、佇列、恢復及結果部分。

- [ ] UAT／PRD 都使用正式 Portal 共用連結；內部新指派不產邀請 token；群組只含同文件同批次合格內部收件人。
- [ ] 每封最多 50 個不同 BCC 地址，超過才拆批；2／50 人各一封、51 人兩封，單人情境仍可寄。實際 MIME 與正文不揭露收件名單。
- [ ] 同信箱只投遞一次，映射回各人的獨立通知 log；外部仍各自專屬邀請，結果畫面按人次顯示而非誤稱封數。
- [ ] 首次排入、維護補列與歷史單 log 工作都進批次處理，共用租約原子領取；並行 worker 不重寄已處理地址，SMTP 不放長交易內。
- [ ] 部分 accepted 只記相應人員成功；明確暫時未寄出者最多 3 次含首次、30／60 秒退避；永久拒收停止，未知／寄送後落庫失敗／過期 processing 不自動整組重寄。
- [ ] transport、worker 與建立文件到通知結果的整合測試通過，保留原外部與 OTP 流程。此票不以「群寄 adapter 寫好」取代實際批次路徑完成。

## 07：催簽與補簽沿用 BCC 並正確處理舊工作

**What to build:** 建立人選取待簽員工催簽或開放補簽時，內部以 BCC 通知本批合格人員；補簽後舊批次不會再覆蓋新結果。

**Blocked by:** 06 BCC 邀請與投遞機制。

**Tasks coverage:** T031；T024/T026/T032–T035/T037 的催簽、補簽、每日額度與 supersede 部分。

- [ ] 人工催簽只寄本次選取且合格的人，保留台北每日一次限制及批次重送去重；外部依原 token 世代逐人寄送。
- [ ] 內部通知資格依文件期間與指派狀態判斷，不再要求 invitation token 或其期限。
- [ ] 補簽同交易失效舊未完成通知並建立新批次；排隊中／領取中／延遲完成的工作不能改寫新批次結果。
- [ ] 暫時失敗只合併本批未寄出地址重試，已受理／永久失敗／未知結果不被維護工作重送。
- [ ] 建立人畫面的操作與逐人結果、混合名單、跨日與競態整合驗收通過。

## 08：無 Email 員工仍可被指派與簽署

**What to build:** 文件名單中即使有無 Email 員工仍可發起及補簽；員工經人資另行通知後自行登入即可完成本人文件。

**Blocked by:** 04 員工簽署、07 催簽與補簽。

**Tasks coverage:** T025/T029/T036；T030/T031/T037 的缺信箱、跳過紀錄與容量部分。

- [ ] 選人及發起畫面將無信箱視為不可 Email 通知，不阻擋指派；後端保留 nullable Email 且仍驗證真實員工身分。
- [ ] 發起、催簽及補簽保留無信箱者指派，通知 skipped／RECIPIENT_UNAVAILABLE，不記 delivered、不入 SMTP，其他有信箱者照常群寄。
- [ ] 全無信箱與混合名單均可完成適用操作；無信箱員工自行登入可看到並簽署本人文件。
- [ ] 上游查詢故障及身分無效仍失敗，外部無有效 Email 仍不得當作內部例外；不加手填信箱、人資通知功能或資料表。
- [ ] 1／100／101／6,000 人合成名單與查詢分批回歸通過，既有已發起快照不改寫。

## 09：舊內部邀請改走 Portal，外部 OTP 保持可用

**What to build:** 員工開舊邀請會收到 Portal 引導，舊內部 OTP 憑證不能再讀檔或操作；外部人員的邀請、OTP、簽署與下載不受影響。

**Blocked by:** 05 拒簽與本人副本、07 催簽與補簽。

**Tasks coverage:** T004/T038–T043；歷史佇列分流由 06／07 提供，本票整合驗證。

- [ ] 舊內部 token 在確認 POST 引導固定 Portal，不寄 OTP、不建立外部 session、不揭露文件；邀請 GET 維持無副作用。
- [ ] 已存在內部 cookie 的 task／原檔／簽署／拒簽／副本與重送全部拒絕；畫面顯示員工登入提示及安全目的地，PDF 入口不回登入 HTML。
- [ ] 切換後原待簽與補簽指派可直接走我的電子簽，不需重建或補寄；新舊驗證方式不改寫已完成證據。
- [ ] 外部完整 OTP、簽署／拒簽重送、已簽副本與期限後下載回歸通過；員工 session 不得取得外部指派權限。
- [ ] 舊通知 queue 與新 worker 相容，內部改 BCC、外部照舊，安全測試與歷史證據驗證通過。

## 10：跨專案完整驗收與切換交付

**What to build:** 交付可追溯的 Email→Portal→本人簽署／副本完整旅程，以及可執行的協調上版與回退步驟。

**Blocked by:** 03 Portal 回跳、08 無 Email 員工、09 舊流程切換。

**Tasks coverage:** T044–T047，並彙整每張票的驗收結果。

- [ ] 電子簽必要 lint/test/build/e2e/security 與 Portal PHP 檢查通過；桌面、窄螢幕與跨帳號權限實際驗收留下結果，未測項目列明而非視為通過。
- [ ] 覆蓋內部 BCC、外部逐人、無信箱、登入／改密碼、本人簽署／拒簽／下載、舊 OTP 拒絕及歷史資料不變。
- [ ] UAT／PRD 通知皆連正式 Portal，記錄實際 iframe origin 與資料環境；不把 UAT 信開到 PRD 當作 UAT 端到端通過，不自行改正式配置或同步資料。
- [ ] 切換步驟涵蓋 Portal 先行、舊 worker 在途與未知結果處理、HTTP/client/worker 相容版本、保留 queue/log 及整體回退限制；此票產出交付方案，不自動部署或推送。
- [ ] 文件與 FR／驗收覆蓋完整，說明無 migration／新環境變數、只有 Portal 版控允許清單；按治理要求審查憲章修訂，保留既有規劃票歷史，不虛報已整合。

## 依賴與覆蓋檢查

```text
02 → 04 → 05 ──────────┐
      └────────→ 08    │
06 → 07 ───────→ 08    ├→ 09
      └───────────────┘
03 ──────────────────────┐
08 ──────────────────────┼→ 10
09 ──────────────────────┘
```

09 僅依 05／07；08 不是 09 的前置，兩者可在所需依賴完成後分工。03 不依電子簽新功能即可驗證自動抵達既有列表。06 不依 03 的部署即可驗證產生信件，完整登入旅程集中到 10。

47 個 tasks 全部由上述範圍涵蓋；跨行為的大 task 依驗收子範圍拆入對應票，不應在只完成部分時提前勾整個 task。tasks.md 保留詳細程式位置，票單聚焦使用者結果與阻擋關係。

待確認：這 9 張實作票的粒度與依賴是否合適，是否需要合併或再拆。確認後才依 to-tickets 技能逐張建立本機正式 tickets。
