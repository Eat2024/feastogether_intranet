# Feature Specification: 電子簽 UAT 操作調整

**Feature Branch**: `docs/spec-019-uat-refinements`

**Created**: 2026-11-02

**Status**: Implemented — 六項功能已實作；Spec017 部門整合驗收及 UAT 切換尚待完成

**Input**: UAT 六項調整：歷史重下載不記錄、ZIP 永久沿用、列表搜尋與分頁、組織圖快取 30 分鐘、移除 Email 預檢、歷程由後端提供中文說明。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 歷史重新下載不重複記錄 (Priority: P1)

有下載權限的使用者從歷史下載重新取得檔案時，歷史列表保留原本的匯出紀錄，不因重下載而累積紀錄。

**Why this priority**: 避免列表膨脹，讓紀錄呈現原始匯出操作。

**Independent Test**: 各準備一筆可下載的 Excel、PDF 與 ZIP 歷史紀錄，重新下載後確認檔案可取得，歷史總筆數及原紀錄內容不變。

**Acceptance Scenarios**:

1. **Given** 可下載的 Excel 紀錄，**When** 重新下載，**Then** 依原篩選條件產生 Excel，不新增或改寫歷史紀錄。
2. **Given** 可下載的 PDF 紀錄，**When** 重新下載，**Then** 取得對應簽署人的已完成 PDF，不新增或改寫歷史紀錄。
3. **Given** 已完成且檔案可用的 ZIP 紀錄，**When** 下載該檔案，**Then** 歷史筆數及原紀錄維持不變。
4. **Given** 同一筆有效紀錄，**When** 連續或同時重新下載多次，**Then** 正常提供檔案且不新增歷史紀錄。
5. **Given** 檔案未就緒、資源不存在或無下載權限，**When** 重新下載，**Then** 呈現相應錯誤且不新增或改寫歷史紀錄。
6. **Given** 從原始匯出入口進行新的匯出，**When** 達到既有記錄條件，**Then** 仍依既有規則新增紀錄。

### User Story 2 - ZIP 不限期保存並沿用 (Priority: P1)

使用者第一次成功產生某文件的 ZIP 後，後續下載及匯出申請皆沿用該份 ZIP，不因經過時間而到期、刪除或重新打包。

**Why this priority**: 使用者不需要因保存期限反覆產生檔案，並能持續取得同一份匯出結果。

**Independent Test**: 成功產生 ZIP 後，將時間推進超過原本的七天期限，確認仍可下載相同內容且重複申請不建立新工作。

**Acceptance Scenarios**:

1. **Given** 已成功產生 ZIP，**When** 超過七天或更久後下載，**Then** 仍提供同一份 ZIP，且不顯示保存期限。
2. **Given** 已成功產生 ZIP，**When** 再次申請匯出，**Then** 沿用原工作與檔案，不產生新的歷史紀錄。
3. **Given** ZIP 已產生後又有人完成簽署，**When** 再次申請或下載，**Then** 仍取得原 ZIP，不加入後來完成的副本；畫面須清楚說明內容固定。
4. **Given** 已完成 ZIP 且經過原保存期限，**When** 背景維護執行，**Then** 不得因期限變更為到期或刪除該 ZIP。
5. **Given** ZIP 首次產生失敗或仍在處理，**When** 依既有流程重試或查詢，**Then** 仍可完成首次產生，不受「沿用已完成 ZIP」規則阻擋。

### User Story 3 - 列表搜尋與分頁 (Priority: P1)

使用者在「我的電子簽」及「歷史匯出」使用一個搜尋欄，輸入文件名稱、文件編號或文件建立人，即可找到符合的項目，並以每頁 10 筆的頁碼分頁瀏覽結果。

**Why this priority**: 統一兩個列表的查找方式，減少逐頁尋找文件。

**Independent Test**: 分別輸入只符合名稱、只符合編號、只符合建立人的關鍵字，兩個列表都能找到對應項目。

**Acceptance Scenarios**:

1. **Given** 有權限範圍內的文件，**When** 輸入名稱、編號或建立人的部分文字，**Then** 任一欄位包含該關鍵字即可列出。
2. **Given** 已輸入關鍵字，**When** 清空或只輸入空白，**Then** 恢復目前權限與其他篩選條件內的完整列表。
3. **Given** 搜尋結果跨多頁，**When** 查詢或切換類型／狀態頁籤，**Then** 先搜尋全部可見資料再分頁，頁籤筆數對應搜尋條件，保留關鍵字；變更關鍵字回到第一頁。
4. **Given** 文件建立人與匯出人不同，**When** 搜尋建立人，**Then** 依文件建立人比對，不將匯出人當成建立人。
5. **Given** 關鍵字符合權限範圍外的資料，**When** 搜尋，**Then** 不得顯示該資料或洩漏其筆數。

6. **Given** 任一列表有 23 筆符合條件的資料，**When** 瀏覽各頁，**Then** 共 3 頁，依序顯示 10、10、3 筆，穩定資料下不重複或遺漏。
7. **Given** 位於第 3 頁，**When** 變更關鍵字或狀態／類型頁籤，**Then** 回到第 1 頁；只換頁則保留關鍵字及其他篩選條件。
8. **Given** 搜尋無結果或網址頁碼無效／超出範圍，**When** 開啟列表，**Then** 無結果顯示空狀態，無效頁碼導正至有效範圍，不呈現虛假的空白頁或錯誤筆數。

### User Story 4 - 組織圖快取縮短為半小時 (Priority: P1)

使用者查詢組織圖時，成功取得的資料最多共用 30 分鐘，期滿後下一次查詢重新取得上游資料，減少組織異動延遲。

**Why this priority**: 將既有兩小時的資料更新等待時間縮短。

**Independent Test**: 成功取得資料後，驗證第 1,799 秒仍沿用快取，第 1,800 秒後第一次查詢重新取得資料。

**Acceptance Scenarios**:

1. **Given** 已成功取得組織圖，**When** 30 分鐘內再次查詢，**Then** 共用快取，且讀取不延長期限。
2. **Given** 快取已滿 30 分鐘，**When** 下一次查詢，**Then** 重新取得上游資料，成功後重新計算 30 分鐘。
3. **Given** 沒有人查詢，**When** 快取到期，**Then** 不因到期自行發送背景更新請求。
4. **Given** 上游或快取服務失敗，**When** 查詢，**Then** 沿用既有錯誤處理，不把失敗回應存成有效組織圖。

### User Story 5 - 移除選人階段的 Email 預檢 (Priority: P1)

前端已移除新增簽署人階段的 Email 預檢，後端也移除不再使用的預檢入口。員工沒有有效 Email 時仍可被指派簽署，只略過該員工的郵件通知。

**Why this priority**: 避免選人階段等待信箱檢查，移除無使用者的功能，保留必要的發起及通知行為。

**Independent Test**: 不經預檢直接發起包含有信箱與無信箱員工的文件，兩者皆有簽署指派，但只有有信箱者進入正常寄信流程。

**Acceptance Scenarios**:

1. **Given** 使用者新增簽署人，**When** 選人或編輯名單，**Then** 不執行獨立 Email 預檢，也不要求預檢成功才能發起。
2. **Given** 文件包含有信箱與無信箱的合格員工，**When** 發起簽署，**Then** 保留全部有效指派，無信箱者略過通知且仍可由我的電子簽操作，有信箱者依適用寄信規則通知。
3. **Given** 舊的預檢入口，**When** 呼叫，**Then** 不再提供預檢服務，亦不觸發上游查詢。
4. **Given** 發起時信箱來源服務失敗，**When** 無法確認地址，**Then** 沿用既有來源失敗處理，不把整批查詢失敗當作所有人沒有信箱。

### User Story 6 - 後端提供簽署歷程中文說明 (Priority: P1)

使用者查看簽署歷程時，各事件皆顯示後端統一提供的繁體中文說明，不再看到未翻譯的內部事件代碼。

**Why this priority**: 補齊漏翻譯事件，避免使用者必須理解內部代碼，統一顯示文字來源。

**Independent Test**: 以盤點的 27 種事件逐一驗證中文說明，尤其外部邀請寄送、外部催簽寄送、個人副本失敗及刪除草稿。

**Acceptance Scenarios**:

1. **Given** 已知簽署歷程事件，**When** 後端回傳並於畫面顯示，**Then** 使用統一繁體中文說明，包含目前缺少對照的四種事件。
2. **Given** 補簽或舊版自動停止事件，**When** 查詢歷程，**Then** 同樣提供中文說明與前端可一致處理的操作者結構，不遺漏特殊回應分支，亦不擴大操作者資訊可見範圍。
3. **Given** 未辨識的歷史事件，**When** 顯示，**Then** 顯示「其他簽署歷程事件」，不直接顯示內部代碼或誤認為成功。
4. **Given** 既有稽核與簽署證據，**When** 增加中文顯示說明，**Then** 原始事件與證據不變，授權、排序、分組及狀態顏色維持既有行為。

### Edge Cases

- Excel 沿用原條件讀取當前資料，不保證與首次匯出內容相同；資料變動不回寫原紀錄。
- 重複點擊、並發請求或失敗後重下載均不得產生新紀錄。
- ZIP 不再提供因時間到期而重新產生的流程；尚未成功的工作仍保留重試。
- 已完成 ZIP 若遺失或損毀，回報檔案不可用，不得悄悄改用目前資料重建並宣稱為原檔。
- 既有到期 ZIP 若實體檔案已遭清除，不能只改狀態就宣稱恢復；上線資料處理須先盤點可用產物。
- 持有紀錄識別碼不能略過下載授權。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 歷史下載重新取得 Excel、PDF 或有效 ZIP 時，系統 MUST 不新增匯出歷史紀錄。
- **FR-002**: 系統 MUST 保留原紀錄的匯出人、時間、條件、範圍及筆數，不因重下載改寫或重新排序。
- **FR-003**: 系統 MUST 保留原有內容選取規則：Excel 使用原條件與當前資料，PDF 取得對應完成副本，ZIP 下載既有有效產物。
- **FR-004**: 系統 MUST 保留新匯出及非歷史入口下載的既有記錄規則。
- **FR-005**: 系統 MUST 維持權限、資源存在性及產物就緒檢查；失敗不得新增歷史紀錄。
- **FR-006**: 本需求 MUST NOT 清除既有重複紀錄，亦不新增下載次數、最後下載時間或另一份重下載歷史。

- **FR-007**: 系統 MUST 取消 ZIP 保存期限；已完成且可用的 ZIP 必須持續可下載，不因時間被清除或失效。
- **FR-008**: 同一文件已有可用的完成 ZIP 時，後續匯出申請 MUST 沿用原工作與產物，不建立新工作，不重新打包。
- **FR-009**: ZIP 內容 MUST 固定於原工作快照；後續新增簽署不更新 ZIP，亦不提供因到期而重新產生的操作。
- **FR-010**: 畫面 MUST 移除「保存至」「保存七天」「到期後重新產生」等提示，並說明 ZIP 產生後固定沿用、不含後續新增簽署。
- **FR-011**: 系統 MUST 保留未完成工作的處理、失敗重試、下載授權與完整性檢查；取消保存期限不得擴大下載權限。
- **FR-012**: 既有可用 ZIP MUST 納入不限期保存；已遺失或被清除的 ZIP 不得偽裝為可下載，須在上線規劃明列處置方式。

- **FR-013**: 兩個列表 MUST 使用單一搜尋欄，以文件名稱、文件編號、文件建立人任一符合的 OR 語意搜尋，採部分文字匹配。
- **FR-014**: 搜尋 MUST 去除首尾空白，空值不限制關鍵字；英文字母不分大小寫，百分比與底線等字元視為一般文字，不提供萬用字元語法。
- **FR-015**: 歷史匯出 MUST 新增與我的電子簽一致的搜尋欄；我的電子簽保留既有搜尋功能。建立人指文件建立人，既有建立人員編搜尋也保留。
- **FR-016**: 關鍵字 MUST 與權限、類型及狀態等條件交集套用，先搜尋再分頁，結果筆數使用相同條件；不得只篩選已載入的一頁。

- **FR-017**: 「我的電子簽」及「歷史匯出」MUST 同時提供搜尋與頁碼分頁，每頁 10 筆，頁數依目前權限與篩選後的結果計算；未輸入搜尋條件時仍須分頁。
- **FR-018**: 換頁 MUST 保留搜尋及頁籤條件；變更搜尋或頁籤 MUST 回到第 1 頁。頁碼保存在網址，重新整理可回到相同查詢頁。
- **FR-019**: 無結果 MUST 顯示空狀態；非法頁碼導正至第 1 頁，超出結果範圍導正至最後有效頁。分頁排序須穩定，資料不變時跨頁不得重複或遺漏。

- **FR-020**: 系統 MUST 將組織圖成功資料的共用快取有效期從 120 分鐘改為 30 分鐘，讀取不得續期。
- **FR-021**: 系統 MUST 保留快取過期後按需取得資料的方式，不新增每半小時固定執行的背景排程。
- **FR-022**: 系統 MUST 保留既有環境／上游隔離、跨實例共用、登入限制、資料驗證與錯誤處理；本項僅調整組織圖快取，不改員工資格或信箱查詢政策。

- **FR-023**: 系統 MUST 移除未使用的員工 Email 預檢入口及其專用合約，不再要求選人階段查詢信箱。
- **FR-024**: 發起簽署 MUST 保留取得通知收件地址所需的查詢；員工沒有有效 Email 時保留簽署指派，略過該員工通知，不阻擋其他有效指派發起。
- **FR-025**: 系統 MUST 區分「查詢成功但無有效信箱」與「來源查詢失敗」，保留後者既有錯誤行為；其他流程共用的員工資格與信箱查詢不得因移除預檢而刪除。

- **FR-026**: 後端 MUST 統一提供簽署歷程的繁體中文顯示說明，前端直接使用該說明，不各自維護事件翻譯。
- **FR-027**: 系統 MUST 覆蓋 `history-event-inventory.md` 的 27 種已知事件與特殊補簽回應分支；未知事件顯示中性中文說明。
- **FR-028**: 系統 MUST 保留機器可辨識的事件代碼與原始稽核證據，不改寫資料庫事件或雜湊；中文化不得擴張歷程可見權限或洩漏 metadata。

### Key Entities

- **匯出歷史紀錄**: 原始匯出操作的類型、操作者、時間、範圍及筆數；重下載引用此紀錄，不建立新紀錄。
- **下載產物**: 依既有內容規則提供給具權限使用者的 Excel、已完成 PDF 或有效 ZIP。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Excel、PDF、有效 ZIP 各重下載三次後，歷史新增筆數均為 0。
- **SC-002**: 全部重下載案例的原紀錄時間、匯出人、條件、範圍與筆數保持不變。
- **SC-003**: 成功案例取得符合內容規則的檔案；失敗案例均無新增紀錄。
- **SC-004**: 正常新匯出的歷史記錄回歸案例全部通過。

- **SC-005**: ZIP 完成後第 8 天及第 365 天，仍可下載與原始產物相同的檔案，且背景維護不因時間刪除它。
- **SC-006**: 同一文件完成 ZIP 後，重複申請三次及新增簽署後再次申請，皆沿用原工作與內容，新增工作數為 0。
- **SC-007**: 所有 ZIP 匯出及歷史畫面均不再顯示保存期限或到期重建操作。

- **SC-008**: 兩個列表皆通過名稱、編號、建立人三種單獨匹配、無匹配與清空搜尋案例。
- **SC-009**: 跨頁結果與頁籤筆數符合搜尋條件，所有搜尋案例皆無權限外資料。

- **SC-010**: 兩個列表在無搜尋及有搜尋兩種情況下，23 筆結果皆分為 10、10、3 筆；換頁保留條件且無重複或遺漏。
- **SC-011**: 兩個列表皆通過搜尋重設頁碼、頁籤重設頁碼、重新整理保留頁碼、無結果及超出頁碼案例。

- **SC-012**: 成功快取後第 1,799 秒仍命中，第 1,800 秒起查詢會重新取得資料，期間多次讀取不延後到期時間。
- **SC-013**: 無查詢時不新增上游請求；多個服務實例仍共用相同有效快取。

- **SC-014**: 新增簽署人流程的獨立 Email 預檢請求數為 0，舊入口不再查詢信箱來源。
- **SC-015**: 混合有信箱／無信箱員工的發起案例中，有效指派全部保留，無信箱員工寄信數為 0，仍可進入本人簽署任務。

- **SC-016**: 27 種已知事件均有後端提供的繁體中文說明，前端直接呈現原始事件代碼的案例數為 0。
- **SC-017**: 未知事件及補簽分支皆顯示中文，稽核完整性與原有歷程授權回歸案例全部通過。

## Assumptions

- 本份 spec 收錄六項議題，使用者已確認進入 plan；目前已完成六項實作與驗證，Spec017 整合驗收另行追蹤。
- 「重新下載」指歷史列表取得檔案；議題 2 進一步取消 ZIP 到期與到期重建，未成功工作仍可重試。
- 不新增資料表或欄位，不刪除既有歷史紀錄；ZIP 舊期限與狀態的資料調整另於 plan 盤點；一般請求紀錄與安全稽核不在移除範圍。
- 本議題取代 Spec 015 中 Excel／PDF 重下載新增紀錄的要求，並取代既有 ZIP 七天保存及到期重建規則。
- Spec 017 的同部門下載權限仍適用，整合時不得因停止記錄而繞過授權。

- 議題 3 的「建立人」包含文件建立人姓名與既有支援的員工編號；輸入內容視為一個關鍵字，不拆成多個詞。
