# Feature Specification: 自訂當次匯出檔名

**Feature Branch**: `dev`（本次僅撰寫規格，未建立功能分支）

**Created**: 2026-11-03

**Status**: Implemented — 程式與可執行驗證完成；T012 真實環境驗收待完成

**Input**: 使用者要求新增供前端修改匯出檔名的 API，並以畫面圈選「匯出檔案名稱」輸入框確認入口；要求先撰寫 spec，再進行 code。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 使用自訂名稱匯出 Excel (Priority: P1)

具文件匯出權限的員工，在匯出頁選擇「簽署紀錄清單（Excel）」並填寫檔案名稱，下載時即可取得容易辨識的檔案，不需在下載後手動改名。

**Why this priority**: 直接完成既有輸入框尚未生效的用途，保留原本篩選與匯出流程。

**Independent Test**: 選定一份文件與篩選條件，輸入「年度簽署紀錄」後匯出，確認建議下載名稱為「年度簽署紀錄.xlsx」，資料符合所選條件。

**Acceptance Scenarios**:

1. **Given** 員工具匯出權限，**When** 輸入「年度簽署紀錄」並匯出 Excel，**Then** 系統提供「年度簽署紀錄.xlsx」作為下載名稱。
2. **Given** 已選擇簽署狀態、部門與匯出欄位，**When** 改用自訂檔名匯出，**Then** 資料範圍、欄位與既有匯出紀錄規則維持不變。
3. **Given** 輸入框未填或只有空白，**When** 匯出 Excel，**Then** 使用本功能上線前的預設命名規則。
4. **Given** 名稱前後含空白或已含 `.XLSX`，**When** 匯出，**Then** 去除前後空白並使用單一小寫 `.xlsx`，不重複追加副檔名。
5. **Given** 檔名不合法或驗證失敗，**When** 嘗試匯出，**Then** 不下載檔案、不新增成功匯出紀錄，保留輸入與篩選條件並以繁體中文提示修正。

### User Story 2 - 使用自訂名稱下載 ZIP (Priority: P1)

員工選擇「已簽署文件（PDF，每人一份打包為 ZIP）」後，能以輸入的名稱下載 ZIP，包含首次產生與沿用已完成 ZIP 的情況。

**Why this priority**: 同一個輸入框位於兩種匯出內容之下，兩種選項須有一致且可理解的效果。

**Independent Test**: 對一份已完成 ZIP 的文件填寫「年度已簽文件」並下載，確認下載名稱為「年度已簽文件.zip」，解壓內容與原 ZIP 相同。

**Acceptance Scenarios**:

1. **Given** 尚未產生 ZIP，**When** 填寫名稱、產生 ZIP 並於同頁完成下載，**Then** 下載名稱採用下載操作開始時的輸入值。
2. **Given** 已有可下載 ZIP，**When** 填寫不同名稱下載，**Then** 使用新名稱提供同一份成果，不因改名重新打包或建立新匯出工作。
3. **Given** ZIP 正在產生，**When** 員工於下載前修改輸入框，**Then** 下載採用最新輸入，ZIP 固定範圍與內容不受影響。
4. **Given** 未填名稱，**When** 下載 ZIP，**Then** 使用既有成果的預設檔名。
5. **Given** 兩位有權限的員工同時以不同名稱下載同一 ZIP，**When** 下載完成，**Then** 各自取得所填名稱，彼此與共用成果的名稱及內容不被覆寫。
6. **Given** ZIP 尚未就緒、成果不可用或員工無權限，**When** 使用自訂名稱下載，**Then** 沿用既有失敗規則，不因檔名設定而放行下載。

### User Story 3 - 理解命名規則並修正錯誤 (Priority: P2)

員工能從輸入框提示理解檔名只影響當次下載，並能修正不合法名稱後重新操作。

**Why this priority**: 避免輸入無效卻下載預設名稱，或誤以為改名會影響所有人及歷史紀錄。

**Independent Test**: 依序輸入不合法路徑與合法中文名稱，確認前者顯示錯誤，後者能下載且不需重選篩選條件。

**Acceptance Scenarios**:

1. **Given** 目前顯示「尚未完成」提示，**When** 本功能完成上線，**Then** 提示改為當次下載、留白使用預設名稱與自動處理副檔名的說明。
2. **Given** 已輸入「年度報表.xlsx」，**When** 切換成 ZIP 並下載，**Then** 下載名稱為「年度報表.zip」，不出現「年度報表.xlsx.zip」。
3. **Given** 輸入 `../報表` 或含換行的名稱，**When** 嘗試匯出或下載，**Then** 顯示不合法名稱提示，不默默改名或使用預設值掩蓋錯誤。
4. **Given** 名稱處理請求失敗，**When** 員工修正或重試，**Then** 保留原輸入及篩選條件，且不顯示下載成功。

### Edge Cases

- 名稱為空字串、純空白或省略：視為未指定，維持原預設檔名。
- 名稱含中文、英文、數字、空白、底線、連字號或括號：符合長度及安全規則時保留。
- 名稱等於 `.`、`..`，去除副檔名後為空，或名稱以句點開頭／主檔名以句點結尾：拒絕。
- 包含斜線、反斜線、控制字元、方向控制字元或 `< > : " | ? *`：拒絕；不得因先去除前後空白而忽略換行。
- 系統保留名稱（CON、PRN、AUX、NUL、COM1–COM9、LPT1–LPT9，包含後接副檔名且不分大小寫）：拒絕。
- 去除前後空白後的輸入超過 100 個 Unicode 字元，或最終含副檔名名稱超過 255 UTF-8 bytes：拒絕並提示長度限制。
- 只將結尾的 `.xlsx` 或 `.zip` 視為可正規化的副檔名；其他句點文字保留，最後補上所選格式的副檔名。
- 點擊下載後才修改輸入：已開始的操作使用點擊時的值，下一次操作才套用新值。
- 瀏覽器因本機已有同名檔案而自動加上序號：由瀏覽器處理，不視為系統改名失敗。
- 重新整理或重新進入匯出頁：依本規格的當次設定假設恢復空白，不承諾保留未完成的檔名輸入。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 啟用既有匯出頁的「匯出檔案名稱」輸入框，適用於 Excel 與 ZIP，無須新增另一個改名頁面。（US1、US2）
- **FR-002**: 系統 MUST 提供前端可呼叫的自訂匯出檔名 API，並由後端驗證適用權限與名稱規則；具體路徑、方法、資料傳遞與回應於 plan／contract 階段定義，不以純前端改名取代使用者要求的後端能力。（US1、US2）
- **FR-003**: 空白輸入 MUST 沿用各匯出類型既有預設名稱；合法輸入 MUST 按所選類型提供單一 `.xlsx` 或 `.zip`，依上述副檔名規則處理。（US1-3/4、US2-4、US3-2）
- **FR-004**: 自訂名稱 MUST 僅影響當次下載的檔案名稱，不修改文件標題、原始上傳名稱、簽署副本內容、ZIP 內部 PDF 名稱或既有共用成果。（US1-2、US2-2/5）
- **FR-005**: ZIP 改名 MUST 保留 Spec 019 的固定工作與成果沿用規則，不因名稱不同重新打包，不混入後續簽署資料。（US2-2/3）
- **FR-006**: 名稱的當次性 MUST 確保不同使用者與並行下載互不覆寫；下載操作以操作開始時的輸入為準。（US2-5、Edge Cases）
- **FR-007**: 後端 MUST 拒絕上述不合法字元、保留名稱、超長或非字串的輸入；未知欄位與不支援的匯出類型亦須拒絕，不能只依賴畫面限制。（US1-5、US3-3、Edge Cases）
- **FR-008**: 名稱處理與檔案取得 MUST 沿用有效員工身分、同部門文件可見範圍與既有下載資格；外部簽署憑證不能授權此員工匯出功能。（US2-6）
- **FR-009**: 失敗時 MUST 以繁體中文呈現可修正原因，保留輸入與篩選條件，不回報成功、不默默退回預設檔名。（US1-5、US3-3/4）
- **FR-010**: 名稱驗證失敗 MUST 不產生新的成功匯出紀錄。正常匯出與歷史重下載 MUST 保留 Spec 015／019 的既有記錄規則，單純處理名稱不新增或改寫歷史紀錄。（US1-2/5、US2-2）
- **FR-011**: 啟用後 MUST 移除輸入框尚未支援的提示，提供當次性、預設值與副檔名規則的說明；處理中保留可辨識的忙碌狀態，避免連續點擊重複提交。（US3-1/4）
- **FR-012**: 自訂檔名 MUST 不改變匯出內容與權限裁切，ZIP 大檔下載及續傳能力須維持；檔名不得導致讀取或寫入使用者指定的儲存路徑。（US1-2、US2-2/6、Edge Cases）
- **FR-013**: 自訂檔名可能包含使用者輸入的個資，MUST 不被寫入非必要日誌、錯誤回顯或暴露給其他使用者；傳遞方式須於 plan 檢查敏感資料邊界。（US2-5、US3-3）

### Key Entities

- **當次匯出檔名**：使用者在匯出頁輸入的可選名稱，與所選 Excel／ZIP 類型及該次下載操作相關，不視為文件的永久設定。
- **匯出成果**：依既有條件產生的 Excel 或既有 ZIP；顯示／下載名稱可依當次輸入調整，但資料範圍、內容與既有紀錄語意不因命名而改變。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Excel 與 ZIP 的合法中文、英文、含空白及已含副檔名案例，100% 提供符合規則的建議下載名稱。
- **SC-002**: 兩種匯出的未填、空字串、純空白案例，100% 維持既有預設命名行為。
- **SC-003**: 所有列出的非法輸入與未授權案例，100% 拒絕且不產生成功下載或新增成功匯出紀錄。
- **SC-004**: 兩位員工以不同名稱同時下載同一 ZIP，兩份下載名稱分別正確，共用成果內容、歷史紀錄及匯出工作新增數均無變化。
- **SC-005**: 使用者可在既有匯出頁完成填寫名稱與下載，不增加額外設定頁或手動改名步驟；錯誤後可在原頁修正並完成下載。

## Assumptions

- 使用者圈選的是文件匯出頁的現有輸入框；本次範圍為 Excel 與 ZIP，不涵蓋單人 PDF 下載或 ZIP 內部檔名設定。
- 「當次下載、不持久保存名稱」為依畫面情境採用的範圍假設；使用者未要求歷史改名或文件永久預設值。後續若改為持久設定，須先調整規格及驗收。
- 長度、保留字及副檔名處理為本規格提出的產品規則，尚非現有系統已具備的行為。
- 歷史匯出頁不新增改名入口；從歷史重新下載亦不承諾記住當次輸入名稱，沿用原規則。
- 依賴既有文件授權、Excel 資料取得、ZIP 產製下載與歷史紀錄功能；與 Spec 017 的同部門權限及 Spec 019 的永久沿用規則相容。
- 不新增資料表、環境變數、排程或第三方依賴；若 plan 發現必要性，須先回到規格說明原因與範圍。
- 目前實作與驗證結果見 quickstart；真實入口網與實機瀏覽器的未驗證項目不視為完成。
