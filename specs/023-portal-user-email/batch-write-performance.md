# 5,001 人發起：批次寫入優化量測

量測日期：2026-11-03。此處比較的是 Spec023 已改用本機員工資料後，逐筆寫入與真正批次寫入的差異。**只以發起 HTTP 回應時間代表前端等待，不把通知 worker 耗時算入。**

## 三輪 HTTP 結果

| 次數 | 優化前 HTTP | 優化前 SQL | 優化後 HTTP | 優化後 SQL | SQL 減少率 |
|---|---:|---:|---:|---:|---:|
| 1 | 15.332 s | 50,073 | 1.179 s | 135 | 99.7304% |
| 2 | 14.990 s | 50,073 | 1.195 s | 135 | 99.7304% |
| 3 | 15.088 s | 50,073 | 1.197 s | 135 | 99.7304% |

三輪中位數由 **15.088 秒降為 1.195 秒**，本機合成測試約縮短 92.08%。每輪由 50,073 SQL 降為 135 SQL，少 **49,938 次（99.7304%）**。這不是 UAT 網路或 production SLA 保證。

|---|---:|---:|---:|
| 員工／信箱查核 | 45 (11) | 48 (11) | 49 (11) |
| PDF／欄位處理 | 4 (4) | 7 (4) | 4 (4) |

| 通知明細初建 | 216 (42) | 216 (42) | 214 (42) |
| 稽核鏈批次追加 | 133 (13) | 141 (13) | 141 (13) |
| 其他 HTTP／交易／回應成本 | 462 (23) | 480 (23) | 496 (23) |
| 發起 HTTP 合計 | 1,179 (135) | 1,195 (135) | 1,197 (135) |

## SQL 減少來自哪裡

| 寫入階段 | 優化前 SQL | 優化後 SQL | 改動 |
|---|---:|---:|---|
| 簽署人 | 20,025 | 42 | 先準備信箱／邀請憑證，一次建立；每批 250 人 INSERT + publicId 回查，避免先存後更新 |
| 通知明細 | 10,002 | 42 | 每批 250 筆 INSERT + 完整唯一鍵回查，不推算連續流水號 |
| 稽核鏈 | 20,008 | 13 | 同文件鎖內取得鏈尾，依序計算 5,002 個事件 hash，每批 500 筆寫入 |
| 其他 | 38 | 38 | 主檔讀取、欄位、交易與其餘查詢 |
| 合計 | 50,073 | 135 | 測試另斷言整次 HTTP SQL 少於 500 |

優化前分項依 `/tmp/spec023-initiation-breakdown.log` 的獨立 profiler 輪次：兩次 signer save 為 10,002／10,023 SQL、通知 10,002、稽核 20,008。該輪 HTTP 為 19.110 秒；它只用來確認 SQL 構成，沒有混入上表原先三輪 15.332／14.990／15.088 秒的時間基準。
