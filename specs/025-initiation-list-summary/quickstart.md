# Quickstart — Spec 025 驗收指南

本文件為實作後驗收計畫，不代表測試已執行。

## 前置條件

- 已含 PR #49、#50 與本次實作；使用合成員工與測試文件。
- 本機 MySQL／Redis 可用，e2e 資料庫名稱必須以 feastogether_intranet_test 開頭，禁止連 UAT 執行自動寫入測試。
- 本機前後端與 worker 可分別啟停。不得對共用 UAT 任意停止 worker。
- 用既有安全測試寄信設定避免發送真實通知；不更改正式白名單政策。

## 自動驗證

```bash
pnpm -C server test --runInBand esign-document-query.service.spec.ts
pnpm -C server test:e2e esign-document-list-scale esign-initiation-query esign-initiation-acceptance
pnpm build
pnpm lint
```

測試須涵蓋：大型 input JSON＋256 KiB sort buffer，無排序 JSON 日期投影；多文件查詢數不隨文件數逐筆增加；角色授權；同一讀取快照內成功／失敗競態；重送；讀取不得取得完整名單及憑證。

## 瀏覽器驗收

1. 分別啟動 `pnpm -C server dev`、`pnpm -C client dev`，暫不啟動本機 worker。
2. 使用有權建立文件的測試帳號，建立草稿，先保存與本次發起不同的名單／期間。
3. 選擇 5213 位合成簽署人及新期間，送出發起。確認受理後返回列表，顯示同一文件、發起中、新期間、0/5213。
4. 保持至少 30 秒，重新整理、重新開啟、以原可讀同部門帳號查看，確認相同摘要。日期篩選／排序必須使用新期間。
5. 檢查全部原有異動與提前簽署入口仍拒絕；不因列上有資料就允許簽署。
6. 啟動 `pnpm -C server worker:dev`。成功後 5 秒內自動切換正式狀態，顯示正式統計，無手動重整。
7. 另以合成工作驗證受理後資格失效導致最終失敗：回到原草稿，無部分正式名單；自動重試時仍保留發起中。
8. 檢查快速完成、網路讀取失敗及多分頁情境；不得把已正式成功的快取降回發起中。
9. 比對寄信略過與發起成功，確認寄信結果不影響狀態或分母。

## 效能與證據

- 1、100、5213 人各 20 次，記錄點擊、前置解析完成、受理回應、列表摘要可見、正式終態可見時間。
- 驗證 SC-001 P95 <=3 秒與 SC-003 <=5 秒；另報端到端等待，不省略前置解析時間。
- 分開記錄受理耗時、背景完成耗時與寄信耗時，不將任何一項替代另一項。
- 保存去識別畫面、查詢數、執行計畫及測試結果；不保存組織個資或憑證。
- client 沒有測試框架，前端驗收須明確記錄實際瀏覽器結果，不把 build 通過當作畫面驗收完成。

## 建立時間追加驗收

在草稿、發起中、完成後核對同一文件「建立時間」相同，並與 createdAt 的台北時間一致；欄位位於文件編號後，格式 YYYY/MM/DD HH:mm。改變瀏覽器時區亦須維持台北顯示。確認新增欄位後空列表、載入畫面 colSpan 與窄螢幕捲動正常，既有排序不變。
